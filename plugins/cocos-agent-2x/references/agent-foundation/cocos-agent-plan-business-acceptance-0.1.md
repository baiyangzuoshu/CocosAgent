# Creator 批准计划业务验收 0.1

范围：Creator 2.4.15，修正批准计划仅凭工具成功推进的问题。本文记录实现合同，真实原生面板验收状态另列；不把工具或构建结果当作功能完成。

## 计划合同

新计划使用 JSON `version: 2`。每步保留 `title/description/preconditions/requiredTools/validation/recovery`，增加 `acceptance: { kind }`；kind 只允许 `read/write/restore/runtime/interaction/memory`。`validation` 是可读说明，程序验收由 kind、实际工具回执和原始用户目标共同决定，模型不能提供任意表达式或自行写入 satisfied。

| kind | 程序条件 |
| --- | --- |
| read | 本步骤实际取得 Creator 内容只读回执；设置/技能调用和前一步读取不能替代 |
| write | 本步骤获批准的内容写入、保存账本、最终目标 UUID/哈希/字段读回及适用的编译回执；已有预览和恢复门槛继续生效 |
| restore | 本步骤真实补偿/恢复回执及相应账本、恢复后目标状态读回 |
| runtime | 本步骤新的运行观察，对照前面步骤实际写入的目标、场景和操作；需帧推进、无页面错误、可用图像及适用的预览接受回执 |
| interaction | 当前尚无原生交互结果断言工具，条件保持未满足，不能用截图或模型声明冒充 |
| memory | 本步骤获批准且已持久化的工程记忆变更回执 |

每步所有 requiredTools 都必须在本步骤成功调用。最后一步额外按**原始用户目标**验收整项计划：模型的计划文字、步骤 kind 或“仅编译”说明不能缩减用户要求的功能范围。只读预检不会被要求完成最终写入，但只读步骤组成的计划也不能把用户要求的创建/修改任务判为完成。

## 接线与证据

Host 给 TS 运行时传递已批准步骤的 kind、原始用户目标、步骤顺序和前序工具证据。业务条件由 Creator 适配层注入；通用模型循环保持负责工具编排。任务图和终态使用同一验收规则；Host 推进步骤还要求业务验收通过。

前序证据只来自 Host 收到的真实工具回执，按步骤保存有界白名单投影，保留调用、操作、UUID/hash、字段、阶段与运行身份，排除源码、技能正文、图片字节和凭据。运行观察仅保留图像可用状态。恢复时证据缺失或无法重建即停止；旧的 version 1 计划须先核对已有操作再重新生成，不能直接套用工具成功规则继续。

当前内容验证复用受限节点、Prefab 源及已有 JS 合同。未有对应业务验收适配的写入工作流应在计划阶段报告范围缺口。出现不确定写入继续进入 needs-review，并按原 operationId 对账，业务验收失败不授权自动重试写入。

## 验收状态

本轮目标是合同、Host/TS/面板接线与产品 skill 的实现修复。真实 Creator 原生面板需验证：只读预检可推进；仅读取场景不能完成创建计划；错误目标/陈旧证据/失败编译不能推进；多步写后观察及跨 Host 重启的证据仍正确；交互断言缺失保持未完成；不确定写入不能重试。
