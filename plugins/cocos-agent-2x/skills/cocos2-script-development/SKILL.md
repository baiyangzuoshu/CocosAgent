# Existing JS/TS gameplay changes

Use the Creator native Agent tools. Select the live project and verify the current capabilities before editing. When the target file or asset is not known, use `cocos_2x_project_search` with a narrow query and `scope=code`, `assets`, or `all`; search results are leads, so read the selected file and verify its live UUID/hash before proposing a write. All script paths below are relative to the project's `assets` folder. Do not infer a component's file or a Button's target from its name alone; inspect the relevant scene and the explicitly selected script first.

1. Call `cocos_2x_project_search` when the target file or asset is unknown. Treat search paths as leads; retain the selected file's live UUID and source/meta hashes from `cocos_2x_script_read`. It reads one existing UTF-8 `.js` or `.ts` file up to 64 KiB and requires matching `javascript`/`typescript` metadata. Never search outside assets or ask to read credentials.
2. Make 1–8 small unique `{before, after}` replacements. Call `cocos_2x_script_patch_plan` with `scriptPath`, `scriptUuid`, `expectedSha256` and `edits`. JavaScript receives a syntax parse. TypeScript returns `syntax=creator-compiler-required`; planning does not claim to parse or compile it. Resolve `SCRIPT_STALE`, `EDIT_NOT_UNIQUE` or `SCRIPT_SYNTAX_ERROR` by reading again and revising the proposal, never weakening the check.
3. After the panel's approval, call `cocos_2x_script_patch` with `input.action=apply`, a new UUID `operationId`, and the exact planned identity/edits. Creator refreshes the corresponding importer, checks unchanged UUID/metadata, and verifies exact quick-compile source content/path in a fresh destination inline source map and parses src/dst output; when there is no inline map, it uses the separate map and compiler stats. A mismatched inline map cannot fall back to success. If exact TS compile evidence is unavailable, keep the original operation ID and stop. Query `cocos_2x_script_operation_get` and read source again. **`needs-runtime` proves compilation/readback, not functionality.**
4. Reopen or reload the preview and actually exercise the requested behavior. For runtime errors or a saved-but-broken scene, use `cocos2-runtime-observation` to inspect the same active scene name and UUID, bounded console events, frame state and canvas image. For a Button node, prefer `node.on('click', handler, this)` with a corresponding `off` at destruction when compatible with existing code. Confirm the existing `cc.Button` component and exact hierarchy; do not add hidden listeners to unrelated objects or invent a successful click. Record observable state before/after. The observer opens a separate fresh temporary browser for each call; it cannot see clicks performed in an existing visible preview. Keep initial observer receipts and actual input/screenshots/logs as separate evidence. It does not synthesize clicks; disclose when behavior still needs an input test.

## Recovery

- A compile/import failure may leave the proposed source on disk. Preserve the returned operation ID and error; it contains an exact original-source backup. `script.operation.get` is read-only.
- On uncertain output (`needs-review`, timeout or disconnect), stop new writes. Use `cocos_2x_script_patch` with only `{action: reconcile, operationId}` to validate the original record without rewriting, or `{action: compensate, operationId}` to restore the original source and reverify compilation. The panel must approve either action.
- Compensation refuses later developer changes or changed metadata. Do not overwrite, delete the ledger or use another write tool to bypass the refusal.
- Only a `compensated` record may be replayed: `{action: replay, operationId: NEW_UUID, sourceOperationId: ORIGINAL_UUID}`. Read back and test functionality again; then compensate the replay if the task is a temporary acceptance exercise.

This is a Creator 2.4.15 single-file JS/TS contract version 0.2. `cocos_2x_project_search` is read-only and searches JS/TS code plus asset filenames/metadata; it does not read scripts outside `assets/`, search arbitrary system paths or verify component/event bindings. No new script assets, multi-file writes, arbitrary filesystem commands, automatic scene event binding, complete Console history, native builds or 3.x support is implied. Creator native panel acceptance of project search and the TS compile branch is pending. Runtime observation is Web-preview only and its live error-repair case remains pending. Real project acceptance must state the actual environment and evidence.
