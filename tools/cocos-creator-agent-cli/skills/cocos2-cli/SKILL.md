# Cocos Creator CLI

Use the standalone `cocos-creator-agent` command for MCP setup, Creator Skill installation, terminal automation, CLI updates, project extension lifecycle, and local bridge operations. The CLI owns and starts the MCP server and packages the workflow Skills; neither requires a separate Host plugin. It is independent of the retired Creator-native CocosAgent and works without Codex or Claude.

## Check and install

1. Run `cocos-creator-agent version --format json` to identify the installed CLI and Creator contract version.
2. If the command is missing, use a versioned tarball from the [CLI Releases](https://github.com/baiyangzuoshu/CocosAgent/releases). For repository development, install from `tools/cocos-creator-agent-cli/`.
3. Check for releases with `cocos-creator-agent self-update --check`; run `cocos-creator-agent self-update` only when an update is needed. A CLI release does not exist until its matching version tag has published the GitHub Release assets. For private repositories, provide `GH_TOKEN`/`GITHUB_TOKEN` or authenticate GitHub CLI with `gh auth login`; never put a token on the command line.
4. After updating the CLI, verify its version and restart the Host MCP server so its tool catalog is refreshed.

## Configure a Host and install Skills

1. Run `cocos-creator-agent skill show --list` to inspect the bundled Creator router/specialist Skills. Use `skill show <name>` to read one without installing it.
2. Preview installation with `cocos-creator-agent skill install codex --dry-run` or `cocos-creator-agent skill install claude-code --dry-run`. Installation defaults to the user's Skill directory and installs the bundled Creator workflow library. Add `--skill <name>` to select one Skill or `--local` to install under the current project (`.agents/skills` for Codex, `.claude/skills` for Claude Code).
3. Install with `cocos-creator-agent skill install <client>`. Use `skill refresh <client>` after a CLI update to refresh managed copies. Modified or unmanaged targets are preserved and reported; `--force` stores a backup before replacing them. Creator API reference notes are placed beside the installed skills so their relative links work.
4. Preview registration with `cocos-creator-agent mcp configure <codex|claude-code|cursor|vscode> --dry-run`, then configure the desired client. `--local` selects a workspace MCP file for Cursor or VS Code and a project registration for Claude Code; Codex is user-scoped. `mcp status <client> [--local]` and `mcp list` report configuration. A same-name server with different command details is preserved unless `--force` is explicit. Cursor and VS Code configs must be valid JSON; symlinks and malformed/comment-bearing files are left untouched.
5. Restart Codex or Claude Code. The server command is the installed CLI executable running `mcp serve`; tools are discovered from the live CLI command contract and Creator instance.

## Use

- Run `cocos-creator-agent --help` to discover supported commands and flags; use `help <command> [<subcommand>]` or append `--help` for focused usage, and `help search <query>` to search CLI and Creator commands.
- For machine calls, add `--json` or `--format json` to receive versioned error JSON with a stable code and kind. Exit codes: 1 general failure, 2 usage/input, 3 bridge/MCP connection, 4 Creator/project/build workflow, 5 write conflict/reconciliation, 10 test failure.
- Use `--format json` for output the Agent needs to parse.
- Use `catalog --format json` to inspect the command descriptions and input schemas supplied by the CLI contract.
- Use `instances list` before selecting an editor. Pass the exact returned `instanceId` for `capabilities` or `call`; never infer the target from a project name or foreground window.
- Use `bridge status`, `bridge start`, and `bridge stop` for local bridge operations.
- Use `doctor [--project-root <absolute-path>] [--instance <instance-id>]` for read-only CLI, bridge, extension, and Creator identity diagnostics. It does not start a stopped bridge.
- Use `creator installations [--search-root <absolute-path>]` to discover installed macOS Creator bundles and their versions. `project open` selects the unique version match when `--creator` is omitted, or accepts an exact `.app` path explicitly.
- Before opening or switching a Creator project, verify its name, absolute path, Creator version, and open state in Cocos Dashboard. Then use `project open --project-root <absolute-path>`; the CLI validates the project version, reuses a connected matching instance, or launches the matching Creator with `--path` and waits for the live extension plus a matching `creator.project.info` response. `editorReady: true` proves the editor answered for the expected path/version; on timeout, inspect Creator for startup delays or a blocking dialog before retrying. Use `--no-wait-ready` only when process-launch confirmation is sufficient.
- Use `vcs doctor --git-root <absolute-path> --project-root <absolute-path>` for read-only Git/Creator asset integrity checks. Supply the exact Git repository root and a project nested within it; the report does not change the Git index or project files and is not a live AssetDB import receipt.
- Use `vcs diff --git-root <absolute-path> --project-root <absolute-path> --path <assets-relative.fire-or-prefab> [--from <revision>] [--to <revision>]` for serialized scene/Prefab changes between Git versions; use `vcs blame ... --node <node-uuid>` to find the most recent first-parent semantic change for one node. Both commands are read-only.
- Use `vcs conflicts --git-root <absolute-path> --project-root <absolute-path>` to inspect unresolved Git index stages. It compares base/ours/theirs semantically for `.fire` and `.prefab` assets and identifies overlapping fields; it explains but does not resolve or stage the conflict, so review and resolve it manually.
- Use `extension install --project-root <absolute-path>` only for an explicit project installation request. Verify the exact project path before installing and let Creator reload the package before checking the live instance.
- Use `extension status` before update or uninstall. Both operations refuse local changes by default. `--force` preserves a backup under `~/.cocos-creator-agent/extension-backups/`; report the backup path and ask the user before deleting it.
- Reload the exact Creator project after extension install, update, or uninstall; then confirm the live instance reports the expected version and project path.
- Use `extension commands list --instance <id>` to discover live project-local Editor extension commands. The CLI checks the provider contract against the current Creator extension handshake and input schema; call one with `extension command call --instance <id> --provider <provider-id> --command <command-id> --fingerprint <sha256> --input <json>`.
- Project-local extension commands run code inside Creator's main process and are not sandboxed. Trust the provider before invoking it; `write` and `control` commands require Creator's own approval dialog, and interrupted calls are never replayed automatically.
- For direct terminal command automation, use `call --instance <id> --command <id> --input <json> --format json`. The CLI validates against its canonical command contract and returns the Creator receipt.
- Use `diagnostics read --instance <id>` before/after compile or preview to capture the Creator event cursor, compile events, import failures, and editor Console entries.
- Use `creator build --project-root <absolute-path> --creator <exact-2.4.15-app> --platform web-mobile|web-desktop` for a machine-readable Creator CLI build; output defaults to a new folder outside the project. Accept success only when `success: true`, `outputExists: true`, and there is no `failureCode`. Creator Builder may log `Build Failed:` while the process exits 0; the CLI reports `CREATOR_BUILD_REPORTED_FAILURE` and a `failureReason`. A successful build has not yet been accepted in a live project; the empty tank acceptance currently fails because no start scene is registered. Use `creator compile` only for supported native platforms after its SDK/JDK or Xcode preflight passes.
- Use `creator test --instance <id> --session <previewSessionId> --input <actions-and-assertions-json>` to run bounded assertions in the same preview session. It returns nonzero if an assertion fails. It is a runtime smoke check, not a Creator unit-test suite.
- For project test plans, use `creator test --project-root <path> --list` to discover `.cocos-agent/tests.json`, then select suites with `--suite <id>`. Use `--rerun-failed <previous-results.json>` to rerun failed suites only when the canonical project path and manifest hash still match; the rerun writes a fresh report. Node suites can use `--shard <index>/<total>` to split test cases (Node 20.5+); Editor suites with manifest `testIds` split by stable case ID and use the injected `CreatorTest.run()` harness. Node and preview suites support `--coverage` (Node 20.1+); Creator Provider and direct Editor script coverage remain unsupported. All adapters return separate evidence in JSON/JUnit reports. Use `creator watch --project-root <path> --paths '["tests","assets/Scripts"]' --affected` for directory changes and affected-suite regression. Read [the test adapter contract](../../references/2x/14-project-test-runner.md) when configuring tests. Provider and Editor tests require Creator approval; interrupted execution stops watch for manual review.
- Use `creator watch --instance <id> --session <previewSessionId> --paths '["assets/Scripts/Player.ts"]' --input <actions-and-assertions-json>` to rerun those assertions after stable changes to explicitly listed project files. It refreshes and reuses the same preview session, emits newline-delimited JSON, and stops with Ctrl+C. Keep the watch list small; paths are project-relative, must be regular files inside the connected project, and cannot be symlinks.
- Start a Web preview only when the task authorizes running project scripts. `preview start --instance <id> [--port 7456]` requires Creator's native approval and returns an exact `previewSessionId`; use only that ID for `preview observe|screenshot|refresh|interact|stop`.
- Runtime interactions are bounded to a small keyboard whitelist (1–2000 ms per press) and normalized clicks on the game canvas. Assertions are declarative scene/node/Console checks, including simple component data properties for business state. `preview refresh` keeps the same owned browser session ID and confirms scene identity; `preview stop` closes only the Agent-owned Chromium browser, not Creator's preview server.
- Screenshots are saved outside the project under `~/.cocos-creator-agent/captures/` and returned with a SHA-256. Distinguish Creator compile events, browser Console, structured assertions, and screenshot evidence.
- Discover project aliases with `project-tools list --instance <id>`. `.cocos-agent/tools.json` can alias canonical `read`/`plan` and Creator-approved `write`/`control` commands; the mapped command's live schema and capability remain authoritative.
- Use `tasks start --instance <id> --command <id> --input <json>` for an asynchronous command, then retain its task ID. `tasks wait --id <task-id> --after-sequence <N>` waits for the next persisted progress event; `tasks status|list|cancel|resume` read, list, cancel, or recover it. Task records survive bridge restart under `~/.cocos-creator-agent/tasks/`.
- Resume only interrupted reads or documented reconciliation. Script creation/modification, scene-node rename/reparent/active, component-add/property, and asset move/delete/import-settings commits reconcile with their matching `creator.script.*.reconcile`, `creator.scene.node.*.reconcile`, or `creator.asset.*.reconcile` command, using the original `operationId`. Do not replay plans, writes, or controls. Cancellation after dispatch is cooperative and may leave a task needing reconciliation.

The Creator command catalog includes approved JS/TS asset creation and modification, one-file asset move/rename through AssetDB, one-node `active` changes, adding one registered component class, and setting one declared public scalar or supported typed property on an exact component instance. Property descriptors support `Vec2`/`Vec3`/`Size`/`Color`, bounded scalar arrays, and exact AssetDB references to SpriteFrame, Texture2D, AudioClip, Prefab, BitmapFont, or TTFFont. For an asset move, inspect the source UUID, file and `.meta` hashes, importer, type, destination folder, and collision checks from `creator.asset.move.plan`; commit only the reviewed operation ID and plan hash. Creator's native dialog remains required, and reconciliation reads both paths without replaying the move. For an existing script, read the full source and hash first; `creator.script.modify.plan` must receive that exact hash and complete replacement source. Review its target UUID/importer, before/after hashes, `.meta` hash, and source preview. Commit only an authorized operation; Creator's native dialog is still required. The prior source is stored outside the project, and recovery requires a new plan with a fresh source hash. Never replay a write automatically. Reconcile uncertain operations before planning again. Use the returned compile cursor with `creator.diagnostics.read`; distinguish an observed compile event from successful compilation, and do not attribute global diagnostics to a script unless the event names it.

For resource-use checks, `asset references --instance <id> --uuid <asset-uuid>` reports exact UUID matches found in bounded text files under the project `assets/` directory. It excludes the target asset and its own `.meta`; binary formats are skipped. Treat `complete: false` as inconclusive; the scan is evidence for locating serialized/source references, not a guarantee that the asset is unused. `creator.asset.delete.plan` is available only when the scan completes with no incoming text references and the target has no sub-assets; inspect the exact file and `.meta` hashes, then approve the native Creator deletion dialog. The CLI does not create a backup. Reconcile an uncertain delete with its original operation ID and never replay it.

`creator.asset.import-settings.plan`, `.commit`, and `.reconcile` support only PNG/JPEG texture assets and the allowlisted Creator 2.4 importer fields `wrapMode`, `filterMode`, `premultiplyAlpha`, `genMipmaps`, and `packable`. Review the exact UUID, source hash, old full `.meta`, and changed values in the plan. The approved commit saves through AssetDB and confirms the full `.meta` readback while preserving unrelated fields. An uncertain save is reconciled by operation ID; do not replay it. Creator may reimport the texture after settings change.

`creator.scene.compose` adds a bounded set of new nodes, registered components, typed scalar/resource properties, and Button click events through Creator Scene Script. `creator.scene.node.rename` supports one existing node per approved operation, bound to its scene/node/parent UUID, original path/name, and a sibling-unique target name. `creator.scene.node.reparent` binds the original node/parent and the destination parent UUID/path, rejects cycles and sibling-name collisions, and explicitly reports that local transforms remain while world position may change. Existing Button event replacement uses `creator.scene.button-events.set.plan|commit|reconcile` and is bound to one exact `cc.Button` instance; the plan shows the complete old and new event lists and validates target UUIDs, registered component classes, and public handler methods. Scene composition, active-state, transform, rename, reparent, Button event, and component-property writes bind the saved AssetDB `.fire`/`.meta` and confirm persistence only after the expected serialized identities and values read back from disk. Component properties additionally require the public field to be serializable and present on the exact saved component ID/class/owning node; supported typed values, ordered arrays, and exact references are verified semantically. If only memory changed, reconcile reports `save-required`; save manually in Creator and reconcile again. Creator documents no completion acknowledgement for `scene:stash-and-save`, so `sceneSaveCompletionConfirmed` remains false. Component addition/removal and node deletion still report same-session readback plus a save request. Component addition rejects classes with implicit `requireComponent` dependencies and warns that constructors/lifecycle hooks are project code. Existing-node property writes support declared scalars, typed value structs, bounded typed arrays, exact active-scene node/component references, and supported exact resource references on the same Creator extension session; arbitrary project objects and asset-reference arrays remain unsupported. If reconciliation cannot prove the affected component instance, require manual review. The separate CLI extension lifecycle commands install, inspect, update, or remove `packages/cocos-creator-agent-extension/`.

## CLI versus MCP

Use the CLI-owned MCP server for Host-native tool discovery and structured calls; configure it with `cocos-creator-agent mcp configure <client>`. Use direct CLI commands for local installation, bridge lifecycle, terminal scripts, and CI. Both interfaces follow the same live CLI catalog and command contract.
