# Cocos Creator CLI

Use the standalone `cocos-creator-agent` command for MCP setup, Creator Skill installation, terminal automation, CLI updates, project extension lifecycle, and local bridge operations. The CLI owns and starts the MCP server and packages the workflow Skills; neither requires a separate Host plugin. It is independent of the retired Creator-native CocosAgent and works without Codex or Claude.

## Creator version policy

The CLI accepts Creator 2.4.1 through 2.4.16. Commands that discover an editor prefer the highest installed supported patch in descending order (2.4.16, 2.4.15, …, 2.4.1); an explicit `--creator` path takes precedence. Existing supported instances are reused; an explicit patch that conflicts with an already-open instance is refused rather than switching editors. Real-editor acceptance evidence currently covers 2.4.15 only.

## Check and install

1. Run `cocos-creator-agent version --format json` to identify the installed CLI and Creator contract version.
2. If the command is missing, use a versioned tarball from the [CLI Releases](https://github.com/baiyangzuoshu/CocosAgent/releases). For repository development, install from `cocos-creator-agent-cli/`.
3. Check for releases with `cocos-creator-agent self-update --check`; run `cocos-creator-agent self-update` only when an update is needed. A CLI release does not exist until its matching version tag has published the GitHub Release assets. For private repositories, provide `GH_TOKEN`/`GITHUB_TOKEN` or authenticate GitHub CLI with `gh auth login`; never put a token on the command line.
4. After updating the CLI, verify its version and restart the Host MCP server so its tool catalog is refreshed.

## Configure a Host and install Skills

1. Run `cocos-creator-agent skill show --list` to inspect the bundled Creator router/specialist Skills. Use `skill show <name>` to read one without installing it.
2. Preview installation with `cocos-creator-agent skill install codex --dry-run`, `skill install claude-code --dry-run`, or `skill install deepseek-harness --dry-run`. Installation defaults to the user's Skill directory and installs the bundled Creator workflow library. Add `--skill <name>` to select one Skill or `--local` for Codex/Claude project installation. DeepSeek Harness installs to `$DSH_HOME/skills/` (default `~/.dsh/skills/`); use `--dsh-home <path>` for a custom home.
3. Install with `cocos-creator-agent skill install <client>`. Use `skill refresh <client>` after a CLI update to refresh managed copies. Modified or unmanaged targets are preserved and reported; `--force` stores a backup before replacing them. Creator API reference notes are placed beside the installed skills so their relative links work.
4. Preview registration with `cocos-creator-agent mcp configure <codex|claude-code|cursor|vscode|deepseek-harness> --dry-run`, then configure the desired client. DeepSeek Harness writes a marked MCP entry to the selected profile's `cordis.patch.yml` (default profile `web`); use `--profile <name>` and `--dsh-home <path>` for another profile/home. `--local` selects a workspace MCP file for Cursor or VS Code and a project registration for Claude Code; Codex is user-scoped. `mcp status <client> [--local]` and `mcp list` report configuration. A same-name server with different command details is preserved unless `--force` is explicit. Cursor and VS Code configs must be valid JSON; symlinks and malformed/comment-bearing files are left untouched.
5. Restart Codex or Claude Code. The server command is the installed CLI executable running `mcp serve`; tools are discovered from the live CLI command contract and Creator instance.

## Use

- Run `cocos-creator-agent --help` to discover supported commands and flags; use `help <command> [<subcommand>]` or append `--help` for focused usage, and `help search <query>` to search CLI and Creator commands.
- For machine calls, add `--json` or `--format json` to receive versioned error JSON with a stable code and kind. Exit codes: 1 general failure, 2 usage/input, 3 bridge/MCP connection, 4 Creator/project/build workflow, 5 write conflict/reconciliation, 10 test failure.
- Use `--format json` for output the Agent needs to parse.
- Use `cloud actions workflows|runs|jobs|artifacts` to inspect GitHub Actions targets, run status and artifact metadata. `cloud actions dispatch --workflow <id|file> --ref <branch|tag> [--inputs <json>]` starts a configured workflow, and `cloud actions cancel --run <id>` requests cancellation. These explicit remote operations require an Actions-write token; if the network result is uncertain, inspect workflow history before retrying.
- Use `catalog --format json` to inspect the command descriptions and input schemas supplied by the CLI contract.
- Use `instances list` before selecting an editor. Pass the exact returned `instanceId` for `capabilities` or `call`; never infer the target from a project name or foreground window.
- Use `bridge status`, `bridge start`, and `bridge stop` for local bridge operations.
- Use `doctor [--project-root <absolute-path>] [--instance <instance-id>]` for read-only CLI, bridge, extension, and Creator identity diagnostics. It does not start a stopped bridge.
- Use `creator installations [--search-root <absolute-path>]` to discover installed macOS Creator bundles and their versions. `project open`, `creator build`, and `creator compile` choose the highest installed supported patch when `--creator` is omitted, or use the exact supported installation passed explicitly.
- Before opening or switching a Creator project, verify its name, absolute path, Creator version, and open state in Cocos Dashboard. Then use `project open --project-root <absolute-path>`; the CLI validates the project version, reuses a connected supported instance, or launches the highest installed supported patch (unless `--creator` is explicit) with `--path`. If an explicit patch conflicts with an already-open instance, it refuses rather than switching editors. Otherwise, it waits for the live extension plus a matching `creator.project.info` response. `editorReady: true` proves the editor answered for the expected path/version; on timeout, inspect Creator for startup delays or a blocking dialog before retrying. Use `--no-wait-ready` only when process-launch confirmation is sufficient.
- Use `vcs doctor --git-root <absolute-path> --project-root <absolute-path>` for read-only Git/Creator asset integrity checks. Supply the exact Git repository root and a project nested within it; the report does not change the Git index or project files and is not a live AssetDB import receipt.
- Use `vcs diff --git-root <absolute-path> --project-root <absolute-path> --path <assets-relative.fire-or-prefab> [--from <revision>] [--to <revision>]` for serialized scene/Prefab changes between Git versions; use `vcs blame ... --node <node-uuid>` to find the most recent first-parent semantic change for one node. Both commands are read-only.
- Use `vcs conflicts --git-root <absolute-path> --project-root <absolute-path>` to inspect unresolved Git index stages. It compares base/ours/theirs semantically for `.fire` and `.prefab` assets and identifies overlapping fields; it explains but does not resolve or stage the conflict, so review and resolve it manually.
- Use `extension install --project-root <absolute-path>` only for an explicit project installation request. Verify the exact project path before installing and let Creator reload the package before checking the live instance.
- Use `extension status` before update or uninstall. Both operations refuse local changes by default. `--force` preserves a backup under `~/.cocos-creator-agent/extension-backups/`; report the backup path and ask the user before deleting it.
- Reload the exact Creator project after extension install, update, or uninstall; then confirm the live instance reports the expected version and project path.
- Use `extension commands list --instance <id>` to discover live project-local Editor extension commands. The CLI checks the provider contract against the current Creator extension handshake and input schema; call one with `extension command call --instance <id> --provider <provider-id> --command <command-id> --fingerprint <sha256> --input <json>`.
- Project-local extension commands run code inside Creator's main process and are not sandboxed. Trust the provider before invoking it. `write` and `control` commands execute immediately without a Creator dialog; Codex assesses the exact operation and tells the user about material risks before invoking. Interrupted calls are never replayed automatically.
- For direct terminal command automation, use `call --instance <id> --command <id> --input <json> --format json`. The CLI validates against its canonical command contract and returns the Creator receipt.
- Use `diagnostics read --instance <id>` before/after compile or preview to capture the Creator event cursor, compile events, import failures, and editor Console entries.
- Use `diagnostics check --instance <id> [--domain physics|audio|font|render|all] [--session <previewSessionId>] [--platform <target>]` for bounded physics, audio, font, and rendering diagnostics. It reads the active scene and AssetDB; an optional existing Preview session adds runtime evidence and a screenshot. It never starts Preview or edits project content. Report missing evidence as inconclusive, and keep Creator 2.4.15 live evidence separate from the broader supported patch range. See the [domain diagnostics contract](../../../docs/agent-foundation/cocos-cli-domain-diagnostics-contract-2.4.15.md).
- Use `creator build --project-root <absolute-path> [--creator <exact-supported-Creator-app>] --platform web-mobile|web-desktop` for a machine-readable Creator CLI build; output defaults to a new folder outside the project. Accept success only when `success: true`, `outputExists: true`, and there is no `failureCode`. Creator Builder may log `Build Failed:` while the process exits 0; the CLI reports `CREATOR_BUILD_REPORTED_FAILURE` and a `failureReason`. A successful build has not yet been accepted in a live project; the empty tank acceptance currently fails because no start scene is registered. Use `creator compile` only for supported native platforms after its SDK/JDK or Xcode preflight passes.
- Use `creator test --instance <id> --session <previewSessionId> --input <actions-and-assertions-json>` to run bounded assertions in the same preview session. It returns nonzero if an assertion fails. It is a runtime smoke check, not a Creator unit-test suite.
- For project test plans, use `creator test --project-root <path> --list` to discover `.cocos-agent/tests.json`, then select suites with `--suite <id>`. Use `--rerun-failed <previous-results.json>` to rerun failed suites only when the canonical project path and manifest hash still match; the rerun writes a fresh report. Node suites can use `--shard <index>/<total>` to split test cases (Node 20.5+); Editor suites and project-local Preview runtime scripts with manifest `testIds` split by stable case ID and use the injected `CreatorTest.run()` harness. Preview scripts execute in the live `cc` page and are not sandboxed; timeout or uncertain execution closes the Agent-owned browser and stops watch for manual review. `--coverage` supports Node, preview, Creator Provider, and direct Editor suites. Provider commands and Editor scripts return adapter-measured per-file counters with current-source hashes for CLI validation; Preview coverage uses Chromium V8 counters from the exact preview origin. All adapters return separate evidence in JSON/JUnit reports. Use `creator watch --project-root <path> --paths '["tests","assets/Scripts"]' --affected` for directory changes and affected-suite regression. Read [the test adapter contract](../../references/2x/14-project-test-runner.md) when configuring tests. Provider and Editor tests execute on the explicit test command; Codex assesses the test code's risk before running it. Interrupted execution stops watch for manual review.
- Merge a complete shard set with `creator test merge --reports '["/abs/shard-1/results.json","/abs/shard-2/results.json"]'`. The command validates project and manifest identity, source hashes, case assignments, and all shard indexes, then writes one JSON/JUnit report. Coverage stays grouped by shard; failed test cases remain failed.
- Use `creator watch --instance <id> --session <previewSessionId> --paths '["assets/Scripts/Player.ts"]' --input <actions-and-assertions-json>` to rerun those assertions after stable changes to explicitly listed project files. It refreshes and reuses the same preview session, emits newline-delimited JSON, and stops with Ctrl+C. Keep the watch list small; paths are project-relative, must be regular files inside the connected project, and cannot be symlinks.
- Start a Web preview only when the task authorizes running project scripts. `preview start --instance <id> [--port 7456]` runs immediately when invoked and returns an exact `previewSessionId`; Codex should explain material risks from running project code before starting it. Use only that ID for `preview observe|screenshot|refresh|interact|stop`.
- Runtime interactions are bounded to a small keyboard whitelist (1–2000 ms per press) and normalized clicks on the game canvas. Assertions are declarative scene/node/Console checks, including simple component data properties for business state. `preview refresh` keeps the same owned browser session ID and confirms scene identity; `preview stop` closes only the Agent-owned Chromium browser, not Creator's preview server.
- Screenshots are saved outside the project under `~/.cocos-creator-agent/captures/` and returned with a SHA-256. Distinguish Creator compile events, browser Console, structured assertions, and screenshot evidence.
- Discover project aliases with `project-tools list --instance <id>`. `.cocos-agent/tools.json` can alias canonical `read`/`plan` and declared `write`/`control` commands; the mapped command's live schema and capability remain authoritative. Aliases execute immediately without a Creator dialog.
- Use `tasks start --instance <id> --command <id> --input <json>` for an asynchronous command, then retain its task ID. `tasks wait --id <task-id> --after-sequence <N>` waits for the next persisted progress event; `tasks status|list|cancel|resume` read, list, cancel, or recover it. Task records survive bridge restart under `~/.cocos-creator-agent/tasks/`.
- Resume only interrupted reads or documented reconciliation. Script creation/modification, scene-node rename/reparent/active, component-add/property, and asset move/delete/import-settings commits reconcile with their matching `creator.script.*.reconcile`, `creator.scene.node.*.reconcile`, or `creator.asset.*.reconcile` command, using the original `operationId`. Do not replay plans, writes, or controls. Cancellation after dispatch is cooperative and may leave a task needing reconciliation.

The Creator command catalog includes explicit-commit JS/TS asset creation and modification, one-file asset move/rename through AssetDB, one-node `active` changes, adding one registered component class, and setting one declared public scalar or supported typed property on an exact component instance. Property descriptors support `Vec2`/`Vec3`/`Size`/`Color`, bounded scalar arrays, and exact AssetDB references to SpriteFrame, Texture2D, AudioClip, Prefab, BitmapFont, or TTFFont. For an asset move, inspect the source UUID, file and `.meta` hashes, importer, type, destination folder, and collision checks from `creator.asset.move.plan`; invoke commit with only the reviewed operation ID and plan hash. The extension rechecks before-state and reconciliation reads both paths without replaying the move. For an existing script, read the full source and hash first; `creator.script.modify.plan` must receive that exact hash and complete replacement source. Review its target UUID/importer, before/after hashes, `.meta` hash, and source preview. Codex assesses the change and tells the user about material risks before invoking commit. The prior source is stored outside the project, and recovery requires a new plan with a fresh source hash. Never replay a write automatically. Reconcile uncertain operations before planning again. Use the returned compile cursor with `creator.diagnostics.read`; distinguish an observed compile event from successful compilation, and do not attribute global diagnostics to a script unless the event names it.

For resource-use checks, `asset references --instance <id> --uuid <asset-uuid>` reports exact UUID matches found in bounded text files under the project `assets/` directory. It excludes the target asset and its own `.meta`; binary formats are skipped. Treat `complete: false` as inconclusive; the scan is evidence for locating serialized/source references, not a guarantee that the asset is unused. `creator.asset.delete.plan` is available only when the scan completes with no incoming text references and the target has no sub-assets; inspect the exact file and `.meta` hashes. Deletion is permanent and the CLI does not create a backup, so Codex should explain this risk to the user before invoking commit. No Creator dialog opens. Reconcile an uncertain delete with its original operation ID and never replay it.

`creator.asset.import-settings.plan`, `.commit`, and `.reconcile` support only PNG/JPEG texture assets and the allowlisted Creator 2.4 importer fields `wrapMode`, `filterMode`, `premultiplyAlpha`, `genMipmaps`, and `packable`. Review the exact UUID, source hash, old full `.meta`, and changed values in the plan. The explicit commit call saves through AssetDB and confirms the full `.meta` readback while preserving unrelated fields. An uncertain save is reconciled by operation ID; do not replay it. Creator may reimport the texture after settings change.

`creator.scene.compose` adds up to 32 new nodes (depth 6), 64 registered components, typed scalar/resource/exact node or component-reference properties, and up to 32 UI event-list bindings (12 entries each) through Creator Scene Script. Legacy `buttonEvents` input remains supported; `uiEvents` covers all 12 whitelisted event properties across Button, Toggle, ToggleContainer, Slider, ScrollView, PageView, and EditBox. Optional `anchorX`/`anchorY` extend node transforms. `creator.scene.node.rename` supports one existing node per exact plan/commit operation, bound to its scene/node/parent UUID, original path/name, and a sibling-unique target name. `creator.scene.node.reparent` binds the original node/parent and the destination parent UUID/path, rejects cycles and sibling-name collisions, and explicitly reports that local transforms remain while world position may change. Existing Button event replacement uses `creator.scene.button-events.set.plan|commit|reconcile` and is bound to one exact `cc.Button` instance; the plan shows the complete old and new event lists and validates target UUIDs, registered component classes, and public handler methods. Scene composition, active-state, transform, rename, reparent, Button event, and component-property writes bind the saved AssetDB `.fire`/`.meta` and confirm persistence only after the expected serialized identities and values read back from disk. Component properties additionally require the public field to be serializable and present on the exact saved component ID/class/owning node; supported typed values, ordered arrays, and exact references are verified semantically. If only memory changed, reconcile reports `save-required`; save manually in Creator and reconcile again. Creator documents no completion acknowledgement for `scene:stash-and-save`, so `sceneSaveCompletionConfirmed` remains false. Component addition/removal and node deletion still report same-session readback plus a save request. Component addition rejects classes with implicit `requireComponent` dependencies and warns that constructors/lifecycle hooks are project code. Existing-node property writes support declared scalars, typed value structs, bounded typed arrays, exact active-scene node/component references, and supported exact resource references on the same Creator extension session. Font properties typed as `cc.Font` accept TTFFont and BitmapFont assets through the base asset type; arbitrary project objects and asset-reference arrays remain unsupported. `creator.scene.ui.inspect` reads bounded typed public properties and current event lists for Button, Toggle, ToggleContainer, Slider, ScrollView, PageView, and EditBox on one exact scene node. `creator.scene.compose.compensate.plan|commit|reconcile` derives a node-deletion inverse from one completed, persisted composition, refuses live or saved-state drift, and verifies restoration of the original scene hashes. If reconciliation cannot prove the affected component instance, require manual review. The separate CLI extension lifecycle commands install, inspect, update, or remove `packages/cocos-creator-agent-extension/`.

## CLI versus MCP

Use the CLI-owned MCP server for Host-native tool discovery and structured calls; configure it with `cocos-creator-agent mcp configure <client>`. Use direct CLI commands for local installation, bridge lifecycle, terminal scripts, and CI. Both interfaces follow the same live CLI catalog and command contract.
