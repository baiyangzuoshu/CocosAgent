# 52 个 Skill 验收口径

验收分成静态质量、离线行为和 Creator 实机三层。三层分开报告，不合成一个总分，因为结构完整、任务表现和编辑器持久化证明的是不同事情。

## 1. 静态质量

- 检查 52 个 `SKILL.md` 均可解析，frontmatter 完整，相对引用可达，辅助脚本无语法错误。
- 保存 Plugin Eval 的逐 Skill 分数、等级和告警。当前扫描为 A34、B13、C5、D0。
- A/B/C 是改进优先级信号，不单独作为行为通过/失败门槛。`description-trigger-weak` 使用字面短语启发式，需人工检查触发边界；token 成本告警也不等同于任务失败。

## 2. 离线行为与回归

每个 Skill 有一条典型正向任务和一条相邻边界任务。提示词使用离线夹具，不连接 Creator/MCP；确定性 verifier 检查路由、范围、证据、结构化输出、空副作用和不虚报实机结果。

| 阶段 | Skill 数 | 用例数 | 用途 |
| --- | ---: | ---: | --- |
| 当前版 | 52 | 104 | 检查所有 Skill 的正向行为和边界路由 |
| 历史基线 | 13 | 26 | 与 `c5d1006bafd6c90c066d81f8bf7dfb02fd61c6f4` 对比内容有改动的 Skill |
| 无目标 Skill 对照 | 15 | 30 | 对 13 个改动 Skill 加当前 C 级的 5 项去重后比较；Codex 仅装无关 sentinel Skill |

验收条件：

- 当前版 104/104 通过；失败按单个用例复核后重跑。
- 13 个基线 Skill 没有原先通过而当前失败的回归项。
- 15 个对照 Skill 都有有效结果；服务超时、路由发现失败或评测器未执行属于基础设施错误，单独记录并续跑，不算 Skill 失败。
- 目标 Skill 与无目标对照表现相同，说明用例还不能区分 Skill 指令和模型通用能力；修订相关用例后重验，不据此声称 Skill 有效。
- 三个阶段固定模型、推理强度和 Codex CLI 版本；保存 suite fingerprint、用量、最终答复、评测输出及 verifier 日志。该样本用于回归判断，不代表统计显著性。

## 3. Creator 2.4.15 实机

对 `suite.json` 中 19 个编辑/内容 Skill 使用隔离工程做真实编辑器读回。每项记录工程名、绝对路径、Creator 版本、打开状态、操作前后值和回读证据。依赖资源身份的操作还要核对 `.meta`、UUID 与引用；源码写盘、Creator 接受、编译/构建和运行时行为分别记录。

开始前先在 Cocos Dashboard 核对项目身份，再核对 Creator 窗口报告的工程路径和版本。身份不一致时停止，不调用项目工具或读写工程。只覆盖 Creator 2.4.15；其他补丁版不能据此判定通过。缺少合格工程或工具条件时记为“未执行”，不得计为通过。

## 结果用语

- **通过**：本层约定的检查项均有可复核证据。
- **失败**：评测实际运行且 Skill 行为或持久化结果不符合合同。
- **基础设施错误**：模型服务、Codex 路由或 Plugin Eval 本身未完成请求；排除在行为分母外并重试。
- **未执行**：实机验收所需工程/工具条件不满足；保留为待验收。

目前没有 Skill 加载事件遥测。因此，离线测到的路由和任务表现只能作为 Skill 效果代理，不能证明 Host 实际加载了某个 Skill。
