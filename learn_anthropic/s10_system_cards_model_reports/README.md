# 第 10 课：如何阅读 Claude 的 System Card 和 Model Report？

**目标：** 能把模型介绍、评估方法、评估结果、部署防护和证据限制分开阅读；遇到一项成绩时，能说清楚它在哪种测试和配置下成立。

## 本课问题

Anthropic 的 Model Report 和 System Card 都介绍 Claude 模型。两者分别适合回答什么问题？看到一项安全或能力评估结果时，怎样避免把测试分数扩大解释成现实世界保证？

## 官方资料

- [Claude 模型 System Cards](https://www.anthropic.com/system-cards)：按模型和发布日期查找卡片；页面说明 System Card 记录模型能力、安全评估和负责任部署决定。
- [Anthropic Transparency Hub：Model Report](https://www.anthropic.com/transparency)：面向读者的模型摘要，并链接到相应 System Card。当前页面显示的 Model Report 日期为 2026-10-02。
- [Transparency Hub：Voluntary Commitments](https://www.anthropic.com/transparency/voluntary-commitments)：概述 System Cards 会报告的能力、基准表现、已知限制、潜在风险、评估与红队结果、训练信息。
- [Challenges in evaluating AI systems](https://www.anthropic.com/research/evaluating-ai-systems)：Anthropic 对人工评估、红队测试等方法挑战的介绍。

核对日期：2026-11-09。官网的型号、报告入口和评估内容会更新；引用时记录具体模型、页面或卡片版本及访问日期。

## 1. 先分清三种资料

| 资料 | 主要回答 | 阅读定位 |
| --- | --- | --- |
| **Model Report** | 这个模型有哪些主要能力、安全评估和部署防护？ | Transparency Hub 提供的摘要入口；摘要会挑选结果，并指向完整 System Card。 |
| **System Card** | 模型如何训练、评估了什么、结果如何、发现哪些限制，部署时采取什么决定？ | 按模型家族发布的详细说明；查看评估设计、表格、附注和限制。 |
| **Risk Report** | 一段时期内有哪些威胁、正在使用哪些缓解措施，整体风险如何判断？ | 横跨模型和威胁模型；与第09课的 RSP 框架相连，不是某个模型 System Card 的另一种标题。 |

可以把阅读路径记成：

```text
Model Report（快速定位） → System Card（核对方法与细节）
                                  ↓
                 Risk Report / RSP（查看跨模型风险与治理）
```

Model Report 方便快速浏览，不能替代其所链接的完整卡片。System Card 是 Anthropic 对自己模型的公开报告，不等于独立审计或对未来表现的保证。

## 2. 逐项拆解一条评估结果

读结果时，尽量将结论改写成：**在某个测试集、任务定义和模型配置下，使用某种评分方式，观察到某个结果。** 可以按下面顺序记录：

| 检查项 | 需要找到的信息 | 为什么要看 |
| --- | --- | --- |
| 对象 | 模型名称、版本、发布日期；测试的是底层模型还是完整产品 | 不同版本、系统提示和产品防护会改变结果适用范围。 |
| 测量目标 | 评估想测的能力或行为；什么算成功、失败或安全回答 | 测试名称本身不足以说明分数的含义。 |
| 方法 | 测试样本、任务、轮数、重复次数、工具环境、评审者 | 这些决定了哪些情形被覆盖、如何生成分数。 |
| 配置 | API 或 Claude.ai；是否有系统提示、工具、分类器或额外防护 | “底层模型能做什么”与“带产品防护的服务表现”不是同一项测量。 |
| 指标 | 分子/分母、百分比含义、越高越好还是越低越好；是否提供置信区间 | 相同的百分比可能代表不同事件，方向也可能相反。 |
| 比较 | 对照模型和版本；任务、提示、评审方式是否一致 | 只有在条件可比时，模型间差异才有解释力。 |
| 限制 | 未覆盖场景、评审偏差、样本规模、评估意识、作者声明的不确定性 | 测试结果不能自动推广到所有用户、任务或真实部署。 |

如果卡片没有披露其中某项，就把它记作“未在该处说明”，不要自行补成确定事实。

## 3. 示例：Model Report 中的“政治观点平衡”评估

以官网当前 Model Report 中的 Claude Sonnet 5.5 摘要为例。报告描述了一项政治观点平衡评估：

1. **测试内容：** 1,350 对请求，覆盖 150 个政治主题；每对请求询问相同事项，但分别从相反政治观点出发。
2. **评分内容：** 另一个 Claude 模型评阅回答，比较两边回答的深度与质量，也记录是否承认其他观点、是否拒答。
3. **运行配置：** 分别测试直接调用 API（没有额外指令）和 Claude.ai（使用产品的常驻 system prompt）。
4. **报告结果：** “观点平衡”指标上，Sonnet 5.5 在 API 为 97.9%，Claude.ai 为 99.0%；对照 Sonnet 5 分别为 86.2% 和 95.7%。但“承认其他观点”的结果并非两种配置都上升：API 为 41.4%（Sonnet 5 为 45.7%），Claude.ai 为 60.2%（Sonnet 5 为 52.9%）。

合理的表述是：**在这项成对请求测试中，Anthropic 报告 Sonnet 5.5 的观点平衡分数高于 Sonnet 5；另一个观点承认指标则因配置不同而呈现不同变化。** 不能据此说模型对所有政治议题都公平、没有偏差，或这些结果已经由独立机构验证。还要注意，评分器是另一个 Claude 模型，这是理解结果时应记录的方法条件。[Model Report 示例与评估说明](https://www.anthropic.com/transparency)

## 4. 将结果与部署决定分开

System Card 中常能找到评估结果和部署决定，但它们是不同层次：

- **评估结果**描述测试中观察到的表现。
- **风险判断**是 Anthropic 根据多类证据作出的解释。
- **部署决定和防护**描述该模型或产品实际采用的限制措施。
- **更广泛的风险判断**需要结合 Risk Report 与 RSP，不能只从一个基准分数推导。

例如，报告若同时提到“在某评估中达到某分数”和“部署时启用某防护”，应分别记录，不能把前者当作后者已经充分有效的证明。若测试没有启用产品防护，也不能直接将测试表现等同于用户在 Claude.ai 中会遇到的表现。

## 5. 常见误读

| 误读 | 更准确的读法 |
| --- | --- |
| “Model Report 说了结果，所以不必看 System Card。” | 摘要用于导航；卡片补充测试细节、限制和更多结果。 |
| “模型在一个基准上分数高，所以现实中总能做好。” | 只报告该任务、样本、评分方式和配置下的结果。 |
| “API 和 Claude.ai 的结果可以混成一个分数。” | 要保留系统提示、工具和产品防护等配置差异。 |
| “报告结果就是独立第三方验证。” | 先看评估是谁设计、谁运行、谁评分；未说明外部审查时，不要称为独立验证。 |
| “不同版本的历史分数天然可直接比较。” | 检查基准、提示、评分标准和版本是否变化；官网注明的常规评估更新也可能改变旧模型结果。 |

## 6. 练习：把结论限制在证据范围内

根据本课 Sonnet 5.5 示例，判断以下说法：

1. “API 和 Claude.ai 都得到 99.0% 的观点平衡分数。”
2. “这项测试用成对请求比较相反观点，并由另一个 Claude 模型评阅回答。”
3. “分数高于 Sonnet 5，证明 Sonnet 5.5 对所有政治问题都中立。”
4. “因为两个配置的指标变化不同，报告应保留配置和指标名称，不能只说‘整体全面改善’。”

**参考答案：** 1 错，API 为 97.9%，Claude.ai 为 99.0%；2 对；3 错，测试只能支持对所测任务和指标的有限结论；4 对。对于“承认其他观点”指标，Sonnet 5.5 在 API 下低于 Sonnet 5，在 Claude.ai 下高于 Sonnet 5。

## 本课结论

先用 Model Report 找到模型和关键结论，再回到 System Card 核对评估对象、方法、配置、指标、比较与限制。最后将观察结果、Anthropic 的风险判断和部署防护分开记述；跨模型的整体风险再查 Risk Report 与 RSP。这样写出的结论才保留了报告本身的范围。

## 范围与时效

- 示例依据 Transparency Hub 于 2026-10-02 标注的 Model Report 内容，核对日期为 2026-11-09。
- 模型、评估结果、基准版本与部署措施可能更新；复用数字前，应从 [System Cards 索引](https://www.anthropic.com/system-cards)重新进入最新卡片。
- 本课复述 Anthropic 发布的评估和解释，不构成对其评估设计、数据或执行情况的独立审计。
