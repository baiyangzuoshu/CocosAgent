# Cocos CLI UI 编辑验收矩阵（Creator 2.4.15）

本矩阵拆分 **Creator 引擎注册、CLI 接口覆盖、实机证据** 三种状态。引擎清单来自 `2.4.15engine/cocos2d/core/components/index.js`；CLI 场景 Inspector 名单来自 `creator-extension/scene.js` 的 `UI_COMPONENT_CLASS_NAMES`；UI 事件字段来自 `UI_EVENT_PROPERTIES`；Widget/Layout 运行时刷新来自 `bridge/runtime-preview.mjs`。静态注册或通用属性合同不等于该组件的写入已经实机验收。

状态判定分开记录接口和证据：CLI 检查列为“有”或属性/事件列有明确命令，表示**接口已实现**；当前证据列写有 Creator 2.4.15 操作轨迹及关闭/重开读回，才表示相应字段的**实机验收通过**；“后续验收”列及明确标注的“仍待验证”描述未覆盖的字段、组件或运行时行为。`实机基线` 只证明曾创建/挂载、读取或编辑代表字段，不表示穷举；`字段往返` 表示保存、CLI 重开/读回和来源补偿通过；`接口具备` 表示存在调用路径但没有该组件的实机闭环；`待补接口` 表示当前缺少专用检查或运行时交互入口。静态合同和单测不能替代实机验收。

## 下一批操作顺序

1. **完成 UI 组件边界验收**：PageView 三页翻转、端点页码保持和 Web Preview 数值回弹已通过；接着确认 Free 模式非等宽页面完整排版、回弹中间帧视觉效果、设备触摸/惯性和 ScrollView 更多 View/Content 尺寸组合。每轮用 CLI 临时夹具，检查状态数值、截图和 Console，再来源补偿、CLI 关闭/重开并比对场景与 `.meta` 基线。
2. **补齐 UI 样式和字段**：ProgressBar 继续验收反向 FILLED/RADIAL、不同 SpriteFrame；Toggle 验收勾选标记、背景及按压/禁用外观和事件多目标/清空边界；EditBox 验证 `placeholder` 代理字段安全映射、移动端原生键盘和目标平台行为。按矩阵逐字段区分写入读回与运行效果，对不支持组合验证明确拒绝。
3. **扩展 Prefab 任意编辑**：从已有末尾内置组件删除扩展到更多可无损恢复组件；逐步覆盖同节点多组件、组件依赖、节点/组件/资源引用与事件列表。每类都完成计划、提交、关闭/重开读回、来源补偿和二次哈希核对；无法可靠恢复的字段保留为明确拒绝。
4. **验收目标平台组件**：SafeArea 的 CLI 挂载、Inspector 字段、Widget 依赖和恢复闭环已通过；下一步在可用设备验证安全区适配。SubContextView 仍需核对目标平台及子域配置后验证 FPS 字段和平台运行。Web Preview 不能代替设备安全区或小游戏子域证据；环境不可用时明确保留未验收。
5. **整理 CLI 与 Unity CLI 的范围差异**：维护能力矩阵，区分 Cocos 本地编辑器、构建/测试、GitHub Actions 与 Prefab/UI 操作；Unity Licensing、Unity Cloud、Unity 专有协作服务只作为不适用项记录，不为表面功能数量引入 Cocos 侧无对应服务的依赖。

每个单项均遵循 CLI 计划 → CLI 提交 → 必要时 CLI 关闭/重开 → 同实例核验工程路径和 Creator 版本 → 活动对象及磁盘 `.fire`/`.meta` 读回 → 来源补偿 → 再次关闭/重开及哈希读回。当前范围只推进 Creator 2.4.15；不使用桌面 UI 自动化。
