# CocosAgent Token 用量统计与优化顺序 0.1

日期：2026-10-18。范围：Creator 2.4.15 原生 Assistant、TypeScript 内核及 Creator 管理的 Host。源码与本地检查已完成，并取得两项原生 Ask 只读样本的日志/持久化证据，其中第一项的面板汇总和请求明细已核对。其他请求类别与 Provider 账单仍待分别验收。

## 优化顺序

1. **建立任务级用量基线。** 记录任务理解、主循环、会话历史摘要与运行中上下文摘要的每次实际请求，包括失败和重试；面板按任务汇总。本文对应本轮实现。
2. **去掉重复输入。** 已实现原生 TS 内核的等价 JSON 回执去重、活动历史复用和运行内摘要缓存，并为 Host 跨回合历史加入字节预算及历史原文按需注入；TypeScript/桥接回归已通过，最新 Host 改动的 Creator 原生复测待做。完整证据、调用配对、目标身份、哈希、未决验收与恢复状态继续保留。实现范围和对照见下节。
3. **精简常驻知识。** 已接入原生 `native-lazy` 提示配置：基础规则与名称/描述索引常驻，专题正文及引用按需读入。Creator 的权限、能力和身份校验由 Host 持续执行。本地编译、自动化回归与元数据测量完成，尚未部署原生验收。
4. **按任务提供工具。** 已保留完整注册表和底层 schema 校验，模型先获得轻量入口和已验证意图/验收所需工具，读取专题技能后自动启用相关工具组；命令参数只投影已选命令分支。恢复锁生效时沿用原恢复工具。本地编译、自动化回归与元数据测量完成，尚未部署原生验收。
5. **减少不必要的模型轮次。** 将确定性的准备与校验留在 Host；再根据请求日志决定是否引入无依赖只读批量操作。写入审批、依赖关系与失败边界分别核对。

每项优化都使用相同任务比较输入/输出 token、模型请求次数、完成率和人工介入。先按现有产品范围落实 s07、s08 和统一运行链路；不以实现全部上游章节数量衡量 token 效率。

## Provider 用量合同

DeepSeek 字段依据：[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)、[Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)。仅接受非负安全整数，缺失或非法值为 `null`；不从其他字段推算未返回的用量。

| 原始字段 | 内部字段 | 含义 |
| --- | --- | --- |
| `prompt_tokens` | `inputTokens` | 本次输入 |
| `completion_tokens` | `outputTokens` | 本次输出 |
| `total_tokens` | `totalTokens` | 接口报告的本次合计 |
| `prompt_cache_hit_tokens` | `cacheHitTokens` | 输入中的缓存命中部分 |
| `prompt_cache_miss_tokens` | `cacheMissTokens` | 输入中的缓存未命中部分 |
| `completion_tokens_details.reasoning_tokens` | `reasoningTokens` | 输出中的推理部分 |

缓存命中字段缺失时，接受 `prompt_tokens_details.cached_tokens` 作为接口提供的别名。两个命中字段不相加；缓存命中/未命中不再加到输入或总量，推理 token 不再加到输出。

每次请求记录一个独立 `requestId`、Provider、模型、用途、开始时间、耗时、HTTP 状态、完成/失败状态、标准化错误码和 usage。不记录请求正文、模型正文、凭据或完整原始响应。

用途为：

- `task-understanding`：任务动作前的无工具意图请求。
- `main-loop`：Agent 内核中的模型请求，每次重试拥有新的请求 ID。
- `summary`：历史摘要，`summaryKind=conversation` 表示 Host 在本轮准备阶段生成的会话摘要，`context` 表示内核运行中的上下文摘要。

收到 usage 后即使意图 JSON 或模型工具调用无法解析，仍保留本次用量。网络失败或未返回 usage 的请求保留记录，其用量未知。没有实际发起摘要请求时不增加请求数。

## 记录、汇总与展示

- Provider 的 `ModelResponse.usage` 传回内核；`model.responded` 事件继续携带该值。
- 每次请求单独产生 `model.usage` 记录，Host 按请求 ID 去重。`model.responded` 中的同一 usage 不再次累计。
- 原生适配器返回 `modelUsageRequests` 和 `modelUsage`；Host 再合并准备阶段的会话摘要，写入同一任务记录。只有返回结果未送达事件时才补入对应请求。
- 任务记录持久化总量、按用途分项和请求明细。每个字段有独立 `coverage`：例如两次请求只有一次返回 `totalTokens=120`，面板显示 `120（1/2 次有数据）`，表示已知部分，不声称完整总量。
- 面板实时更新任务用量，可展开每次请求；历史任务恢复时显示保存的统计。旧记录没有统计时不补造零值。
- 本地日志导出与状态存储仅为六个用量字段放行非负安全整数或 `null`；凭据 token、字符串和对象伪装的用量字段仍被过滤。
- 本轮不计算费用：token 统计与实际计费核对需使用匹配的 Provider 价格及账单来源。
