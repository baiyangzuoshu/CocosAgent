# CocosAgent 对照 Unity Agent 的开发方向调整

日期：2026-10-17。状态：**开发方向已确认；M1 通用项目开发工具合同已定义，`project.search` 源码桥接和 skill 已接入；Creator 原生验收待做，其余 M1 写入命令仍在规划/待实现。** 当前版本范围为 Cocos Creator 2.4.15。

本记录承接用户本轮确认的 Unity Agent 对比与开发建议，调整[原生 Agent 开发计划](cocos-agent-real-project-development-plan.md)的执行优先级。此前的源码、合同、测试与实机证据按各自版本保留；本记录不改变历史验收结果。与旧文档中的“近期顺序”冲突时，以本记录和主计划的 2026-10-17 方向调整为准。

## 1. 产品目标与架构决定

主目标调整为：**让开发者在 Creator 内描述真实游戏功能，Agent 能理解现有项目，完成代码、场景、组件和资源的协同修改，读取编译与运行反馈，并交付可审阅、可恢复的结果。**

- 保留 Creator 原生面板、TypeScript + Node.js 内核、Creator 管理的 Host/内部 MCP、Provider 接口及既有命令与操作账本。
- 将主要开发投入转向可组合的项目开发基础能力：项目搜索与文件操作、JS/TS 开发、编辑器对象与组件操作、运行观察和功能验证。
- 新增操作优先复用公共的目标发现、类型/schema、权限、差异、读回和回执设施；不把每个业务功能都固化为新的专属命令或自然语言正则分支。
- 以 LinkUpClient 的实际任务作为主要产品验收样本，隔离工程用于故障注入和回归；任务目标须来自当前项目检查，不复用历史 UUID 或凭空假设业务 API。
- 首版继续由自有内核独立执行。Gateway 接入成熟 coding agent 作为可选架构评估，不作为本轮实施承诺，也不改变当前不依赖 Codex 或外部 Agent 的启动边界。

“通用”指 Creator 项目内可复用的开发能力。通用 shell、任意系统文件写入、团队/子 Agent 和定时任务仍不在产品范围。项目代码及配置文件操作也须有明确注册根、文件类型和读写合同；场景、Prefab 与资源元数据继续使用经核对的 Creator API 和身份校验。

## 2. Unity 对照与当前差距

对照依据为本轮可读取的 Unity 官方产品页和 Assistant **2.9.0-pre.2** 文档，不声称该版本是最新版本，也未进行同条件产品实测。公开文档列出的能力不等于所有任务都能成功，更不证明两者安全性或效果高低。

| 维度 | Unity 官方公开能力 | CocosAgent 当前依据 | 本轮调整 |
| --- | --- | --- | --- |
| 产品入口 | 内置 Assistant 的 Ask/Plan/Agent；另有 Gateway、CLI/MCP | 原生三模式已有接线和部分实机证据 | 复用面板和内核，优先完善任务能力 |
| 项目理解 | 项目文件、场景对象与组件查询；截图及代码操作 | 场景快照、选择上下文、现有脚本读取和 PNG 查询 | 补项目代码/资源搜索、引用关系与组件属性发现 |
| 代码与编辑器开发 | 编辑/运行 C#，内置动作及自定义工具组合 | 现有 JS 精确替换、有限字段及专属资源流程 | 补 JS/TS 新建、多文件修改、组件和事件绑定；不直接照搬 C# 执行机制 |
| 权限 | 操作级 Allow / Ask Permission / Deny，可配置 Autorun | 写入逐次审批及程序门槛 | 设计用户明确选择的任务权限范围，保留审批与拒绝模式 |
| 恢复 | 可启用逐提示 Git checkpoint，使用项目外本地存储 | 精确 operation 对账、补偿和重放 | 增加任务差异与 checkpoint 方案，复用账本核对副作用 |
| 技能与工具扩展 | 项目/用户/包内 skill，按需加载；自动发现自定义工具 | 产品包内 skill/reference 读取与哈希校验 | 增加项目级 skill 和项目工具注册合同 |
| Agent 来源 | 自有 Assistant 与 Gateway 第三方 Agent | 自建 TS 内核，当前 Provider 适配主要为 DeepSeek | 保留自有内核，Gateway 单独评估，不作为前置条件 |

本项目当前证据以[主计划最新状态](cocos-agent-real-project-development-plan.md)及其链接轨迹为准。现有脚本合同限定已有 JS 的读取和精确替换；原生交互断言入口仍缺失。部分观察和记忆能力已在隔离 Creator 工程实测，不能据此宣称真实项目通用开发闭环已经完成。

### M1：以可组合能力扩展现有合同

- 搜索先覆盖项目代码和资产身份，返回有界结果及可继续定位的信息；编辑前读取当前文件、引用和目标身份。
- 新建脚本经 AssetDB 导入并读回 `.meta`/UUID；多文件修改逐项记录实际状态和失败副作用，不声称原子事务；TS 支持须单独核对 Creator 2.4.15 编译链。
- 组件属性通过当前实例的类型、序列化和可编辑信息发现；对无法可靠保存/读回的字段返回明确不可用原因。组件添加、删除及事件绑定分别核对引用与恢复行为。
- 当前内核中的任务意图和最终目标校验继续使用，后续按通用动作/schema 演进；用户原文、模型提议、授权范围和成功证据各有明确职责。

### M2：把运行反馈接入实际修改循环

- 优先解决已复现的项目预览归属与观察会话问题；状态、截图、日志和交互应来自同一可核对工程/场景/预览会话。
- 根据样本所需行为提供有限输入和业务状态查询，先形成一个可重复功能断言，再扩充其他输入类型。
- 编译通过、运行无捕获错误、画面可见与业务断言分别记录。不能测量的条件列为未验收，保留停止原因和人工检查项。

### M3：项目知识扩展边界

- `plugins/cocos-agent-2x/skills/` 继续是内置产品 skill 的权威来源。项目 skill 发现根为 `.cocos-agent/skills/<id>/SKILL.md`，与内置 skill 分开列出、按需读取，不允许覆盖内置来源；reference 只接受已列目录 ID 和精确 SHA-256。
- `.cocos-agent/agent-tools.json` 声明的项目工具只绑定固定 Creator 2.4.15 命令。命令的真实 schema、访问级别、目标范围、成功回执和恢复合同由底层命令继承；manifest 不能放宽。MCP 在调用前核对 manifest SHA、注册工程与实时能力；写入继续逐次审批并进入原账本。
- 可选 `enabled:false` 会禁用绑定；移除项目 skill 目录会停止发现。索引与读取时哈希不匹配、manifest 变更或读写分类不匹配均拒绝执行。
- 0.1 仅接入声明式语义命令别名；不加载项目代码、不执行 shell/任意回调。业务 API 的知识可由 skill 描述；若需要真正新增 API 调用，仍须补 Creator 命令合同、桥接和验收。普通 Node `vm`、工具描述或 skill 哈希不称为安全沙箱。
- 当前工作区没有 LinkUpClient 工程内容，因此尚未整理其真实框架约定、UI 工作流或业务 API，也没有修改该工程。接线实现不等于 LinkUpClient 项目内容就绪或原生实机验收通过。完整合同见[项目扩展合同](cocos-agent-project-extensions-0.1.md)。

### M4：任务恢复和权限的设计约束

- 新权限模式需明确工程、run/计划、命令/操作类别、对象范围、有效期与撤销行为。现有逐次写入审批在新模式完成实现及实机验收前继续生效；文档更新不授予运行时权限。
- checkpoint 设计采用项目外的工程隔离用户目录，记录授权范围内的目标基线身份与哈希；只允许 current-after 精确匹配时提出补偿。基线匹配表示已恢复/无变化；第三种值、身份或引用不匹配均为冲突并停止。场景/Prefab/Asset 优先走 Creator operation compensation，不能覆盖用户后续改动或范围外文件。
- 任务审阅由 run receipts 分类汇总代码、场景/Prefab 和其他写入并关联 operationId；当前卡片明确是回执范围，不冒充完整 Git/磁盘 diff。待补真实最终读回与用户可操作的 checkpoint 创建/冲突处理入口。
- 取消等待已分发命令回执并阻止后续工具，不等于回滚。重启后只读 run 可标中断；有活动或未决写入标 needs-review，锁住新写入并先按原 operationId 对账；只有完全匹配原合同才进入受控补偿，冲突绝不自动覆盖或 replay。详见[任务审阅、权限与 Checkpoint 合同](cocos-agent-task-review-recovery-0.1.md)。

## 4. 首个真实功能样本与指标

候选样本为“在现有界面增加一个按钮，绑定项目逻辑，并更新界面状态”。领取奖励/更新金币只是说明开发跨度的例子，不预设 LinkUpClient 已有对应系统。

实施前从 LinkUpClient 当前代码、场景/Prefab 和项目约定中选择一个确实存在的需求，固定以下信息：

1. 原始需求、可观察的成功条件和明确的排除范围。
2. 当前工程/Creator/扩展/技能版本，相关文件哈希、资源与对象 UUID、已有未决操作和用户未提交改动。
3. 计划修改、授权范围、编译与运行检查、实际交互步骤，以及保留结果或恢复基线的方式。

从 Creator 面板直发该任务；不得把外部 harness、隔离工程或人工代做改动记为原生 Agent 自动完成。人工点击或修复可以作为独立证据，但必须计入人工介入。

样本记录包括：需求与验收条件、run/operation 身份、完成/部分完成/失败、失败原因、人工介入次数及类型、实际差异、编译和运行/交互证据、取消或恢复结果、耗时、工具调用和 Provider 可提供的 token/费用。没有用量数据时明确缺失，不估造数值。

建立样本集后统一报告任务成功率（通过全部必需条件的任务数/纳入统计的任务数）、人工介入分布、耗时及恢复结果；保留所有失败与部分完成样本。发布门槛在获得基线后制定，skill 数量、工具数量和自动测试数量不单独代表产品完成度。

### 2026-10-17 M5 验收执行记录

本轮已在 LinkUpClient Creator 2.4.15 原生面板完成一项 Ask 只读前置核对，详见[完整记录](traces/cocos-agent-m5-linkup-ask-20261017.md)。运行 ID `486b35b1-7a9c-4090-8bfa-027e1d8e73d0`，约 29.4 秒，调用 6 项只读工具；完整读取项目约定、场景和 skill 成功。模型提出“登录失败时是否缺少可见兜底”的候选，却没有 TypeScript 源码和运行证据，故未据此开始写入。原生复测（run log `2026-10-17T01-41-56-322Z-fc21ddd3.jsonl`）证明旧 Host 仍在内存，扩展/MCP/Agent 包版本不匹配导致 `project.search` 缺失、脚本合同不可用。随后统一了 Host/Creator 包脚本合同，实现有界 `project.search` 执行分发、`.ts` 内容搜索与 TS importer 读取，单元测试 11/11；扩展目录合同测试通过；打包与升级测试 4/4。Creator 包已重建并安全升级到 LinkUpClient 磁盘目录的 0.3.18，旧版保留 rollback。Creator 进程重载还未完成；本轮 CUA 后续无法重新绑定 2.4.15 编辑器窗口，因此当前内存版本、扩展指纹、能力目录和 TS 真实读回未知。没有读取 TS 业务源码或修改游戏场景。

统一样本记录口径如下，之后每次 Creator 面板提交的功能任务都保留一条记录，包括失败、部分完成、取消和需人工恢复的任务。前置 Ask、能力盘点等准备工作单独记录，不混入功能成功率分母：

| 字段 | 记录规则 |
| --- | --- |
| 样本身份 | `sampleId`、Creator 面板 `runId`、项目路径/工程身份、Creator 2.4.15 与扩展/Host/skill 版本；记录开始时间和结束时间 |
| 基线 | 需求原文、可观察验收条件与排除范围；相关文件 SHA、资源/节点 UUID、未决 operation、既有工作区差异；写入授权范围 |
| 结果 | `success` 仅当所有预先约定的必需条件均由 Creator 编译、运行、交互或磁盘读回证据通过；否则按 `partial`、`failed`、`cancelled`、`needs-review` 等终态记录并说明原因 |
| 人工介入 | 分开计数用户写入批准、人工补充提示/目标、编辑器手工操作、人工输入/业务检查、人工修复/恢复；仅提交任务本身记为 0 项后续介入。另保留介入事件列表，避免只报合计 |
| 耗时 | 从面板接受任务的时间到终态回执的墙钟时间；若等待编辑器/用户中断，记录等待区间并同时保留总墙钟时间，不擅自扣除 |
| 恢复 | `not-needed`、`compensation-passed`、`no-effect-confirmed`、`conflict`、`unresolved` 等；关联 operationId、before/after 身份与哈希及编辑器/磁盘读回证据。任务成功与恢复成功分开统计 |
| 成本与证据 | 工具调用数、Provider token/费用（不可得时写 `unavailable`）、Console/编译结果、运行会话与截图引用、完整任务审阅结果；不得以模拟测试替代面板任务 |

汇总指标以所有已提交且有唯一面板 runId 的功能样本为分母：任务成功率 = `success` 样本数 / 纳入样本数；同时报告失败/部分完成/取消/需审阅数量、各类人工介入次数及样本分布、中位数与范围耗时、恢复结果分布。尚未启动的尝试不计入分母，单独列作环境阻塞；样本数为 0 时写“未采集”，不写 0% 成功率。当前记录为：LinkUpClient 前置 Ask 1 项（不纳入功能样本）；有效功能样本 **0**；功能成功率、写入批准/介入、恢复结果均**未采集**。当前阻塞是 Creator 主进程尚未重载新扩展，导致 0.3.18 原生合同兼容与 TS 搜索/读取未确认；因此仍未对 TS 业务路径下结论。

## 5. 既有能力与风险的安排

- 保留实例/工程/版本校验、读写区分、项目约定门槛、陈旧状态拒绝、UUID/哈希、保存读回、操作回执、不确定写入对账和失败补偿。
- 既有摘要、任务图、Goal Loop、长期记忆和 Provider 修复继续记录未验收项。涉及授权、数据完整性或当前任务可靠性的缺陷先修；其他独立验收按真实功能需要安排，不要求完成所有历史研究分支才能推进 M1。
- PNG、内容 release、Bundle、性能压力、原生测量和引擎源码优化保留已有成果，由真实任务或测量问题触发继续投入。已完成历史 operation 不重复 apply/replay。
- 3.x 继续暂停新增；Windows 或其他平台支持不从 Node 可运行、自动测试或 Unity 支持范围推定。
- Gateway 后续若进入实施，单独记录外部 Agent 生命周期、凭据、依赖、权限、取消和工具一致性，并明确与当前独立原生模式的关系。该决定需基于具体集成评估。

新增能力继续按“命令合同 → 编辑器桥接 → 产品/项目 skill → 原生实机验收”推进，分别登记状态。checkpoint、权限策略、工具注册等新范围需先补对应合同，再实现；本次仅更新开发方向文档。
