# Creator 2.4.15 自由 Agent 任务验收 0.1

日期：2026-10-13。扩展版本：0.3.13。状态：TS/Host/面板实现与自动回归完成，Creator 重载后的真实工程任务验收待做。

## 修复目标

自由输入的修改任务不能仅凭一条成功读取回执标为完成。此前默认 `requiredTools: ['*']` 可被场景读取满足。本次由 Creator Host 定义验收条件，再按实际工具回执验证；模型的完成声明、Todo 完成状态和自行创建的弱任务条件不能替代根任务验收。

Creator 工具、写入审批、项目约定哈希、技能读取、恢复锁和操作账本继续承担各自约束。内核只编排目标评估与有界续跑，Creator 回执语义由产品模块处理。

## 任务范围

- 明确只读任务：需要实际 Creator 内容读取；实例/能力、skill、任务图元数据不能替代内容证据。
- 明确修改任务：要求内容写入、对应账本、最终对象读回及必要的编译/运行证据。
- 混合“检查，然后创建”任务：按修改任务判定；读取前缀不会降级验收条件。
- 显式记忆变更：要求经批准且持久化成功的记忆变更回执；不能替代场景/脚本修改。
- 不明确的任务：保留目标澄清项，不退回通用成功回执。

范围识别目前采用有界的中英文任务线索，是保守分类器，不是通用自然语言目标理解。复杂表述可能需要明确目标。用户明确要求“仅编译/不运行”时，验收范围可止于源码读回和编译，不宣称交互功能通过。

已批准 Plan 步骤继续使用 Host 提供的显式逐步工具条件；本次重点修复未提供显式 `goalCriteria` 的自由任务。批准计划步骤的工具名覆盖不等于整个游戏功能已验收。

## 回执条件

| 条件 | 所需证据 |
| --- | --- |
| 内容写入 | 本轮确实调用获批准的内容写工具；明确 operationId；场景/Prefab 的 editor/disk 为 passed，脚本的当前源码/UUID/meta 哈希匹配。预览启动、只读通用命令和无关记忆变更不计为内容写入 |
| 账本读回 | 最后一次内容写入之后，读取本轮对应 operationId 的操作记录；不同 operationId 不能替代 |
| 最终目标读回 | 最后一次内容写入之后核对相同节点 UUID 和预期字段，或脚本/Prefab UUID 与源码哈希。多次修改同一对象以最终目标状态读回；旧读取随新写入失效 |
| 脚本编译 | 本轮涉及脚本写入时，必须有 Creator 编译成功回执；语法解析和脚本计划不是编译证明 |
| 运行观察 | 对 UI/场景/脚本等相应任务，在写后观察匹配场景 UUID/目标 UUID、推进的帧、零捕获错误与可用截图。要求预览验收的写入，还须在观察后按同一 operationId 验收 |
| 交互功能 | 点击/网络/登录等不能由初始页面截图证明。当前没有原生交互验收工具，这类验收条件保持未满足并展示缺口；忽略日志或模型自述中的“interactionVerified”样式声明 |

第一版自由内容写入验证重点覆盖现有 `scene.node.create/patch`、`scene.pngSprite`、`prefab.source.patch` 和 `script.patch` 合同；实际可用性仍由实时能力目录决定。其他批次、构建或 release 任务没有完整通用自由任务验证器时，应报告缺少对应验收合同，不能借另一项节点修改取得完成状态。

这些条件证明操作和已定义验收阶段，不证明任意游戏功能的全部语义正确，也不把静态节点检查当成实际用户输入。0.3.14 已补 Prefab 场景进程桥接，0.3.15 已实现同一可见页面的持续运行观察；两者真实 Creator 验收仍待完成，自动输入及交互结果断言入口仍缺失。

## 任务图与终态

根条件的 `toolMatch` 与 `receiptRequirement` 随任务图保存。语义验证器缺失或规则未知时拒绝满足条件。带语义条件的证据每次按当前完整回执重算，不能沿用已陈旧的历史满足状态。

验收在持久化任务图存在和不存在时均生效；已恢复任务的旧弱条件不能覆盖当前请求的根条件。模型停止时最多续跑两次，工具/轮次预算、取消及不确定写入恢复锁继续生效。达到预算后也重新评估缺项，不依赖模型再次返回总结。

未满足条件时保存 `stopped` 与 `goalEvaluation.satisfied=false`，根任务保留 `in_progress`；已有 `cancelled`、`needs-review` 等状态保留其含义。Host 保存并导出最终验收结果。面板任务卡显示“未完成”及具体缺项，重启恢复后仍可查看；模型的“弹窗已完成”文本不会替代这些结果。
