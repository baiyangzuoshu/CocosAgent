# 阶段 4 分面验证：磁盘依赖、编辑器导入与原生平台

本页分别记录 Creator 2.4.15 与 3.8.7 的编辑器、Chrome 预览和 macOS 原生运行面。公开行为先核对对应版本的[2.4 资源工作流程](https://docs.cocos.com/creator/2.4/manual/zh/asset-workflow/index.html)和[3.8 资源工作流](https://docs.cocos.com/creator/3.8/manual/zh/asset/asset-workflow.html)；下表中的依赖计数来自本机示例，不能推广为引擎固定常量。磁盘与导入的原始记录见[2.x](traces/2.4.15-disk-import-validation.jsonl)与[3.x](traces/3.8.7-disk-import-validation.jsonl)。

| 验证面 | 2.4.15 | 3.8.7 | 证据边界 |
| --- | --- | --- | --- |
| 已落盘场景的资源依赖 | `helloworld.fire` 中直接出现 2 个不同 UUID；运行时活动 Scene 的依赖表有 5 条直接边、3 个不同 UUID，递归得到 6 项且均已缓存。SpriteFrame 与其贴图主资源都能在缓存中找到。 | `main.scene` 中有 6 次 `__uuid__` 引用、4 个不同 UUID；运行时依赖表有 5 条直接边、4 个不同 UUID，递归得到 53 项且均已缓存。`soldier.prefab` 单独递归得到 17 项，含 FBX 导入子资源。 | `.fire`/`.scene` 文本引用、运行时依赖表和 Asset 缓存是不同层；这些数字属于本示例当前场景。 |
| Chrome 预览中真实磁盘场景切换 | 旧 `helloworld.fire` → 新 `stage4-empty.fire`；旧场景独有 SpriteFrame 初始引用 1。源场景 `autoReleaseAssets=false` 时，切换后引用 0，350ms 仍缓存有效；重新载入后在内存中设 `true`，切换后引用 0，350ms 已移出缓存并失效。 | 旧 `main.scene` → 新 `stage4-empty.scene`；旧场景独有 `soldier.prefab` 初始引用 1。`false` 时引用降到 0 后仍缓存有效；独立预览里在内存中设 `true` 后，350ms 已移出缓存并失效。 | [2.x 原始转录](traces/2.4.15-disk-scene-switch.jsonl)与[3.x 原始转录](traces/3.8.7-disk-scene-switch.jsonl)。两版新场景均由对应编辑器创建并落盘；`true` 只修改运行时旧 Scene，源场景文件仍为 `false`。这是 Chrome 预览证据，350ms 仅为采样点。 |
| macOS 原生进程中真实磁盘场景切换 | 独立 Mac 包启动后调用 `cc.director.loadScene('stage4-empty')`；SpriteFrame 在源 Scene `false` 时引用降至 0、350ms 仍缓存有效；运行时旧 Scene 设为 `true` 时，回调仍缓存有效、350ms 采样已移除并失效。 | 独立 Mac 包启动后调用 `director.loadScene('stage4-empty')`；`soldier.prefab` 在 `false` 时引用降至 0、350ms 仍缓存有效；运行时旧 Scene 设为 `true` 时，回调仍缓存有效、350ms 采样已移除并失效。 | [2.x 原始日志](traces/2.4.15-mac-native-disk-scene-switch.jsonl)与[3.x 原始日志](traces/3.8.7-mac-native-disk-scene-switch.jsonl)。新增场景实际纳入包配置；每个分支独立进程启动。源场景仍为 `false`，开启只在运行时修改活动旧 Scene；350ms 是采样点。 |
| 编辑器导入新资源 | 在 `assets/resources/` 创建 `stage4-probe.json` 后，2.4 编辑器生成 `.meta`（`importer=json`、UUID `5ade...`）、`library/imports/5a/...json`，资源管理器与属性检查器显示 JSON 内容。 | 3.8 编辑器对对应 JSON 生成 `.meta`（`importer=json`、UUID `f6a2...`）、`library/f6/...json`，资源管理器与属性检查器显示 JSON 内容。 | 两版资源管理器都确认导入；`library` 是生成产物，不能作为源文件修改入口。两版 UUID 独立，不可互用。 |
| 导入资源的预览加载与释放 | 新页面中对象缓存原本没有该 UUID；`cc.resources.load('stage4-probe', cc.JsonAsset)` 返回 `cc_JsonAsset`，数据 `version=2.4.15`，与缓存同实例，回调净 `refCount=0`；自身 `addRef/decRef` 后缓存移除、对象失效。 | 同样从冷对象缓存加载为 `JsonAsset`，数据 `version=3.8.7`，回调净 `refCount=0`；自身 `addRef/decRef` 后缓存移除、对象失效。 | 这验证了“文件 → 编辑器导入 → Bundle 路径 → 浏览器运行时对象”的闭环；并未测试下载文件缓存清理。 |
| macOS 原生包与场景 | Creator 的 Mac 构建、编译成功；`hello_world-desktop.app` 显示 Cocos 标志与 `Hello, World!`。新 JSON 出现在 `build/jsb-link/assets/resources/import/`。 | Creator 的 Mac 构建、Make 成功；`CocosGame.app` 显示岛屿、树木、石头、角色与天空。新 JSON 出现在 `build/mac/data/assets/resources/import/`。 | 证明两版本机包可运行并显示原场景；其他平台需分别验证。 |
| macOS 原生进程内 JSON 生命周期 | 冷缓存 `cc.resources.load` 回调取得 `cc.JsonAsset`，UUID/版本正确，与缓存同实例，净 `refCount=0`；探针 `addRef` 后为 1，非强制 `releaseUnusedAssets` 后仍缓存有效；`decRef` 后立即仍缓存，约 350ms 后采样已移除且失效。 | 冷缓存 `resources.load` 回调取得 `cc.JsonAsset`，UUID/版本正确，与缓存同实例，净 `refCount=0`；自身 `addRef` 后为 1，非强制释放后仍缓存有效；`decRef` 后立即仍缓存，约 350ms 后采样已移除且失效。 | [2.x 原始日志](traces/2.4.15-mac-native-asset-lifecycle.jsonl)与[3.x 原始日志](traces/3.8.7-mac-native-asset-lifecycle.jsonl)来自对应 Mac 进程；350ms 是探针采样等待，不是引擎承诺的释放延迟。 |

两份 JSON 是保留在示例中的最小可复现资源。它们的 `.meta` 由各自编辑器生成，不应手工改写 UUID。2.x 文件位于 `2.4.15NewProject/assets/resources/`，3.x 文件位于真实目录名带逗号的 `3.8,7NewProject/assets/resources/`。

原生验证遵循两版独立的[2.4 原生发布说明](https://docs.cocos.com/creator/2.4/manual/zh/publish/publish-native.html)和[3.8 原生发布说明](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/native-options.html)。探针临时插入生成的 Mac 包脚本，分别观察启动后冷缓存 JSON 生命周期和实际磁盘场景切换；场景切换每个开关分支均由独立进程启动，并记录目标资源缓存、引用和有效性。测试后已恢复包内原脚本，并以原文件 SHA-256 核对。2.x 原生日志从进程输出及 `/private/tmp` 保存；3.x Mac 包对 `/private/tmp` 的写入未产生日志，改用 `jsb.fileUtils.getWritablePath()`，本机对应 `~/Library/Containers/com.cocos.stage4probe/Data/Documents/`。这些原始日志已复制到本仓库 `docs/`。没有修改两套示例的组件或场景源文件，也没有强制释放正在显示的资源。
