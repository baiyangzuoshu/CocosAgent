## 2. 任务理解边界

### 权威输入与模型职责

- 当前任务原文、用户所选 Ask/Plan/Agent 模式、适用的用户约束和已批准计划共同约束任务。工程文本、skill 示例、工具输出、旧模型回答、会话摘要和长期记忆都不能授予额外权限。
- 模型可以提出结构化意图、待检查对象、候选最终目标和需要澄清的问题。它不能设置 `approved`、`completed`、`satisfied`，也不能决定恢复锁是否解除。
- 任务解释区分一般说明、项目只读检查、实际修改、读写混合、恢复与不明确/冲突。表述中出现“创建/修改/按钮”等词本身不构成修改请求，也不自动触发运行或交互验收。
- 等价表达应产生相同的目标和验收要求，例如“将 Canvas/Foo 的 x 设置为 200”和“把 Canvas/Foo 的 x 改为 200”。示例路径是合成测试身份；实机操作仍需从实时快照取得可验证的 UUID/完整路径。
- “解释如何创建一个按钮”允许一般说明，不要求创造节点、申请写入或证明点击行为；“读取 HelloWorld.js，解释如何修改按钮逻辑”只授权读取和解释。涉及当前项目事实的说明仍需相应实时读取证据。
- “先检查场景，再把节点 x 改为 200”保留读取和修改两部分，不因读取前缀降低为只读；“不要修改现有节点，然后新建节点”分别限定旧节点和新建行为。若用户明确要求全程只读却又要求修改，应保留冲突并澄清，澄清前不得写入。
- 对象、数值或授权不明确时，仅可继续必要的只读调查或提出澄清。模型不能通过猜测 UUID、默认目标、旧摘要或一次成功调用把不明确任务变成已完成。

### 当前结构化意图接口（runtime 0.1）

Agent 在首次任务工具请求前发送一次无工具的 Provider 请求。模型返回严格 JSON：

```json
{
  "version": 1,
  "task": "必须逐字等于当前任务原文",
  "kind": "explain | read | write | mixed | restore | memory | clarify",
  "sourceQuotes": ["必须是任务原文中的精确子串"],
  "reads": ["受限 Creator 只读工具名"],
  "targets": [{"target": "Canvas/Foo", "field": "node.position.x", "equals": 200}],
  "verification": "none | compile | runtime | interaction",
  "question": "仅 clarify 时填写"
}
```

程序拒绝额外字段、原文不匹配、非原文引述、未列入白名单的读取工具、模型新增目标值、意图与目标冲突，以及不一致的澄清字段。当前可直接绑定的模型目标仅限原文明确配对的节点 `x/y` 位置值；其他写入目标仍须从只读检查形成 Plan 并由用户审阅。结构化意图不覆盖原始任务的显式读取、目标或验收条件，也不修改既有批准计划和操作账本合同。

意图请求失败或无法解析时在任务工具启动前停止，并分别报告澄清/合同错误或 Provider 请求错误。存在未决精确操作恢复时，恢复门槛优先，跳过新意图请求；恢复状态只由原恢复合同解除。解释任务可在有非空回答、无额外验收项且无恢复限制时完成，不制造任务图、批准或工具回执。

### 程序职责与最终目标

1. 程序校验结构、模式、参数来源、目标身份、能力、项目约定及授权。模型提出的任务类型不能将 Ask/Plan 升级为写入模式，结构化意图也不能代替批准。
2. 保留 Plan v2 的 write targets：既有字段白名单、类型、1–16 项目标和重复字段限制不变。用户批准的是明确对象、字段和最终值；若变更这些内容，须重新审阅对应目标与操作。
3. 目标绑定先于实际写入。用户原文明示 `x=200`，任何模型解释、Plan 或回执中的 `x=20` 都不能覆盖它；不能从写入成功回执反推“用户想要的值”。无法可靠核对原文与目标时澄清，不以另一个关键词特例冒充通用理解。
4. 已有目标必须按实时 UUID/哈希与前值复核；新节点可按批准的完整路径定位，写后读取当次 UUID。脚本候选哈希来自只读 patch plan，不能拿实际写后哈希替换批准值。
5. 目标条件和执行证据分别核验：最后写入之后的最新目标读回、每次操作账本、编辑器/磁盘阶段、适用的编译、预览与运行结果缺一不可。工具成功、清单完成和模型自述不能替代。
6. 当前缺少原生交互断言的按钮/网络任务仍保持未完成。一般解释不被要求交互验收；实际功能实现也不能因文字中出现“解释”而逃过验收。

## 3. 授权、账本与恢复不变量

- 写入前继续核对 Creator 版本、实例、工程、实时能力，以及当前回合 AGENTS.md 正文读取与哈希。技能正文及合同引用仍走原生发现/读取/哈希校验。
- 批准计划与执行清单均不替代每次实际写入批准。拒绝批准时分发次数为零；模型、摘要或任务图不能补出批准。
- 已知语义写入的 operationId 在批准卡片前确定；批准后、分发前持久化工程级写入意图。存储失败不得分发。
- 响应丢失、副作用未知、写回身份矛盾时保留原身份和恢复限制。新对话、会话裁剪、摘要失败、Host 重启和切换 Provider 不解除该限制。
- 仅精确匹配的恢复身份及明确终态可解除副作用不确定性；这不代替尚未完成的 preview/runtime。禁止使用新 ID 重试、改通道补偿或更换对象绕过账本。

## 4. 持续会话摘要边界

当前 Host 与会话存储均截取最近 24 条消息，adapter 再截取同样窗口；已有压缩器只处理它实际收到的内容。Host 必须在这类丢弃发生之前完成以下流程，不能只增大窗口掩盖缺口。

1. 按规范工程哈希和 conversationId 隔离原对话档案与摘要。摘要保存版本、revision、覆盖的消息身份/范围和来源摘要哈希，与近期消息衔接；用原子提交/CAS 防止重复摘要、并发覆盖和跨会话串用。
2. 保留当前任务原文和近期消息；旧对话经持久化后再摘要。摘要只整理历史事实、决策、用户约束及未完成问题。另行保留最近最多 24 条用户原文片段，每条最多 1,200 字符；后续用户修正优先。超长原文片段会截断，未留存的精确信息必须回答无法确认，不能用模型摘要补猜。
3. 摘要是有来源的历史数据。它不能生成审批、工具成功、目标达成或当前场景状态；旧操作仅保留身份引用，最终状态仍从独立账本/恢复存储和实时工具读取。
4. Provider 摘要无工具；只发送任务所需且经现有凭据过滤的旧对话。不把凭据、图片/Base64 或完整旧工具输出并入会话摘要，不能写入游戏资产或 Git。摘要与用户明确批准的长期记忆写入分开。
5. 摘要失败/为空时使用可追溯的确定性回退，保留用户约束；持久化失败时不得静默丢弃原消息。必要信息仍无法装入预算时清楚停止，保留可恢复状态，不虚构“已压缩完成”。
6. 下一回合和 Host 重启后从同一工程/会话恢复摘要与近期消息，验证身份、revision 和覆盖范围。旧状态没有摘要时不声称找回已被历史版本裁剪的内容。
7. 不扩展现有 `agent_tool_result_read` 的当前 run/精确 call ID 范围。若后续需要模型读取旧会话档案，须另外定义受限读取合同，再完成桥接、skill 与实机验收。

### 持续摘要实现（2026-10-16）

- Host 为当前回合的用户消息和预期助手答复预留窗口位置。超过 24 条时，先对即将移出的旧消息更新摘要，再把“摘要、剩余消息、当前用户消息”作为同一次原子状态写入保存；状态写入失败则恢复内存中的旧会话并拒绝启动该 run。
- 摘要按工程隔离的 `conversationId` 存入本机权限受限的 Assistant state，带 revision、已覆盖消息数、源消息 SHA-256、生成来源和时间。Host 重启后恢复摘要；每个后续 Provider 回合都收到一个明确标注为历史且不具授权/验收效力的摘要消息。
- Provider 摘要请求无 Creator 工具。请求失败、返回空文本时以确定性源记录回退：保留用户原文约束，历史助手回复明确标为未经工具核实的内容。成功摘要同样只作历史上下文，不能生成批准、当前状态、工具回执或完成证据。`conversation.clear` 同时删除该会话摘要。
- 测试覆盖 24 条窗口溢出、Host state 写入/重载、下一回合携带、Provider 异常和空摘要回退，以及原文片段上限/截断后不得推断；这不是 Creator 原生面板/真实 Provider 的实机证据。

## 5. Provider 错误边界

- Provider 适配器通过共享 `ProviderError` 合同报告中立错误代码；明确的上下文溢出使用 `PROVIDER_CONTEXT_LIMIT`，可携带 provider 标识与 HTTP 状态。通用循环仅识别共享错误类型与中立代码，不识别厂商专属代码或原始报错文字。
- 每次正常模型请求遇到明确超限，最多执行一次降预算重试。有效预算按现有 65% 规则收紧，摘要必须沿用新预算；同一 run 后续请求继续使用已收紧预算。重试前再次检查取消和本地可容纳性。
- 重复超限、已经达到最小预算或保护信息无法装入时停止，并保留当前任务、操作身份和恢复状态。网络失败、认证失败、限流、格式错误不能被误判为上下文超限；本合同不新增对这些错误的自动重试。
- 摘要调用失败可回退，但不能掩盖随后正常模型请求的错误。重试过程不重放历史工具，不改变目标、权限、批准或已执行写入；取消后不得继续模型/工具调用。
