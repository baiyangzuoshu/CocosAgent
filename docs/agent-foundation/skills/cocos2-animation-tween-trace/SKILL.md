# Trace 2.4.15 animation and tween

Use the matching [2.4 animation manual](https://docs.cocos.com/creator/2.4/manual/zh/animation/index.html), [script control](https://docs.cocos.com/creator/2.4/manual/zh/animation/scripting-animation.html) and [tween manual](https://docs.cocos.com/creator/2.4/manual/zh/scripting/tween.html) for public behavior. Read the [independent architecture note](../../../2.x/08-animation-and-effects.md) before the [comparison](../../../comparisons/08-animation-and-effects.md).

1. Identify whether the target is an `AnimationClip` state, a 3D `SkeletonAnimationClip`, a `cc.tween` chain, or a direct action. Record node/component active state, default clip, `playOnLoad`, state name, duration, wrap mode and the exact property being written. For 3D skeletal animation, check that `SkeletonAnimation` has its Model connected; the Model's internal `precomputeJointMatrix` changes the clip curve path. Do not treat it as a public component switch matching 3.8 `useBakedAnimation`.
2. For clips, follow `CCAnimation.play/playAdditive → animation-animator → AnimationState → AnimationManager.update`; distinguish `play` stopping other states from `playAdditive`. Track `pause/resume/stop` and queued state events through `AnimationManager.pushDelayEvent`.
3. For tweens, follow `cocos2d/actions/tween.js::start → _union → cc.director.getActionManager().addAction`. Track the composed action and target identity; `stop` removes the action. This Tween has no instance `pause/resume`: `node.pauseAllActions/resumeAllActions` controls all actions on that node, while an arbitrary object requires ActionManager target handling. For direct `node.runAction`, check `node.active`: CCNode only adds it for active nodes, pauses its target on deactivation and removes actions before destruction. This 2.4.15 path emits the `cc.Action` deprecation warning, but remains relevant to existing projects. Both managers enter `CCDirector.mainLoop` through Scheduler after component `update` and before `lateUpdate`.
4. When a clip and tween write the same property, record the value during component `update`, each manager's update, and `lateUpdate`. Registration order alone does not establish the final visible value. Confirm with a small runtime trace before recommending priority or ownership changes.
   The [temporary 2.4 clip/tween probe](../../probes/stage8-clip-tween-2.4.js) uses `AnimationClip.curveData.props` and the read-only duration's backing field for an in-memory test. Its [fixed-clock Web trace](../../traces/2.4.15-stage8-clip-tween-headless-web.jsonl) shows ActionManager writing `x=40` before AnimationManager writes `x=20` on the first nonzero shared-property step; the clip wins the final sample at 100. The 0.1-second timeline function fires at step 2 and clip `stop/finished` at step 5. Keep this result scoped to the temporary clip and manual `Scheduler.update(0.05)`. Treat animation timeline function events separately from component playback events: `EventAnimCurve` can call an event directly on its first sample, while later crossed keys queue it through AnimationManager.
5. Record Creator patch version, Web/Native platform, time scale, pause state, sample timestamps and event order. The [2.4 Web fixed-clock trace](../../traces/2.4.15-stage8-tween-web.jsonl) confirms ActionManager before AnimationManager and one Node Tween's pause/resume/stop values with manual `Scheduler.update(0.05)`; it does not cover natural RAF, `by`, multiple Tweens on one target, or audio/particles; ordinary clip and shared-property behavior are covered by the separate trace above. Check the [stage 8 validation record](../animation-effects-validation.md) before generalizing.

For 2.4 precomputed skeletal clips, trace `SkeletonAnimationClip._generateJointMatrixCurve → JointMatrixCurve.sample → joint._jointMatrix → SkinnedMeshRenderer._calJointMatrix → fillBuffers`. The renderer may upload the current matrices as a uniform or its own joint texture depending on device capacity. That texture is not 3.8's shared baked clip texture; no 2.4 skeletal runtime trace exists in the supplied demo.

For audio or particle issues, start from the dedicated files listed in the architecture note; do not infer their lifecycle from tween scheduling.
