# Trace 2.4.15 asset lifetime

Confirm the project uses Creator 2.4 and identify whether the observation comes from the editor, browser preview, or a built game. Use the [2.4 resource workflow](https://docs.cocos.com/creator/2.4/manual/zh/asset-workflow/index.html), [Asset Manager](https://docs.cocos.com/creator/2.4/manual/zh/asset-manager/index.html), [Bundle](https://docs.cocos.com/creator/2.4/manual/zh/asset-manager/bundle.html), and [release](https://docs.cocos.com/creator/2.4/manual/zh/asset-manager/release-manager.html) manual pages for public behavior. For internal detail use the local [2.x study](../../../2.x/04-assets-and-loading.md).

1. Trace the **requested asset identity**: API (`cc.resources`, Bundle, or `cc.assetManager`), Bundle name, path and type, `.meta` main/sub UUID, and the scene or prefab's `__uuid__`. Keep source asset, subasset, and runtime request distinct. Do not assume every `assets/` file is loadable by `cc.resources`.
2. For a load failure, follow `bundle.js::load/loadScene` → `CCAssetManager.js::loadAny` → `preprocess.js/config.js/urlTransformer.js` → `pack-manager.js/parser.js/deserialize.js` → `load.js::loadDepends`. Locate the first failing request and whether it is a configuration lookup, missing redirected Bundle, fetch, parse, dependency, or asset `onLoad` failure. If a path matches multiple subassets, check the requested type. `Bundle.loadScene` loads a SceneAsset; `CCDirector` runs it.
3. For preload claims, follow `CCAssetManager.js::preloadAny` to `fetchPipeline`. Check whether a later `load` actually produced an Asset; a completed preload callback alone does not establish that.
4. For memory or invalid assets, record the UUID, `asset.refCount`, `assets.has(uuid)`, caller-held reference, scene `autoReleaseAssets`, static scene dependencies, dynamic assignments, and persistent nodes. Follow `CCAsset.js::addRef/decRef` → `releaseManager.js::{tryRelease,_autoRelease,_free}` and `CCDirector.js::runSceneImmediate`. Count dependency injection and load-request increments **and** `load.js` → `clear(task,true)` decrements; a successful callback can have no net added reference. Separate nonforced `decRef/releaseUnusedAssets` from forced `releaseAsset/Bundle.release/releaseAll`; `utilities.js::cache` does not put SceneAsset into `assets`.
5. If checking behavior live, choose an asset not used by the current scene, and observe preload/load/cache/ref changes before releasing only the experiment's own reference. Verify dependencies before a forced release. Never use `releaseAsset` on a scene asset or visible texture merely to test whether it is retained.
6. For disk/import diagnosis, compare the scene file's `__uuid__` references with `dependUtil.getDeps(scene.uuid)` and `getDepsRecursively(scene.uuid)` in the same preview run; the lists need not have equal lengths. Inspect the source file and editor-generated `.meta` first, then generated `library/` only as an import result. The reproducible cold-load fixture is `2.4.15NewProject/assets/resources/stage4-probe.json` (UUID `5ade5460-c142-47dc-8dd0-82322301d6cc`): confirm it is uncached before `cc.resources.load('stage4-probe', cc.JsonAsset)`, and release only a reference added by the probe. The existing `singleColor.png` was already cached in the measured scene.
   For a real scene-switch probe, first confirm both scene names in the active Bundle's `getSceneInfo`, then choose a UUID in the old Scene's `dependUtil.getDeps` but absent from the new Scene's dependencies. Record target `refCount`, `assets.has(uuid)`, and `cc.isValid(asset,true)` before `director.loadScene`, in its launch callback, and after a delayed sample. In this workspace, `helloworld.fire` → `stage4-empty.fire` makes SpriteFrame `31bc895a-c003-4566-a9f3-2e54ae1c17dc` old-only; the [preview trace](../../traces/2.4.15-disk-scene-switch.jsonl) covers both `autoReleaseAssets` branches. Its `true` branch set the active disk Scene's flag in memory after a fresh preview reload; the source `.fire` still says `false`.
7. For a Mac native report, verify the generated package and app separately from browser preview. The [native JSON trace](../../traces/2.4.15-mac-native-asset-lifecycle.jsonl) measures a cold `cc.resources.load` callback, object-cache identity, net `refCount=0`, a probe-owned `addRef`, nonforced `releaseUnusedAssets`, and `decRef` followed by delayed invalidation. The [native disk-scene trace](../../traces/2.4.15-mac-native-disk-scene-switch.jsonl) independently measures `cc.director.loadScene('stage4-empty')` with each `autoReleaseAssets` branch. Reproduce by placing a temporary probe after `cc.director.runSceneImmediate(scene)` in generated Mac `main.js`, logging to a writable path, then restore that generated file. The traces cover this JSON, the SpriteFrame fixture, and Mac process only; 350ms is a sampling wait, not a release guarantee. The `true` branch modifies the active old Scene in memory; the source `.fire` remains `false`.

Report the earliest unexpected transition with source symbol and evidence type: manual, static source, `.meta/scene` inspection, editor import, browser runtime, or native runtime. If a surface is unavailable, say which conclusion remains open. The [measured 2.x preview cases](../../traces/2.4.15-asset-lifecycle.jsonl) cover SceneAsset, isolated release-manager branches, and Director scene switches with in-memory scenes and assets; the separate [disk scene-switch trace](../../traces/2.4.15-disk-scene-switch.jsonl) covers `loadScene` with editor-created scenes. The [disk/import/Mac record](../../traces/2.4.15-disk-import-validation.jsonl) and [validation matrix](../../asset-validation-matrix.md) distinguish browser and native surfaces. When probing persistent nodes, inspect the new scene's `dependUtil._depends` entry: `_autoRelease` stores transferred `persistDeps` only when that record exists. A synthetic Scene without it does not reproduce a normally loaded scene. Use [stage 4 comparison](../../../comparisons/04-assets-and-loading.md) only after the version's own chain is established.
