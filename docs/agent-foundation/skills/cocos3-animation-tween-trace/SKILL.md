# Trace 3.8.7 animation and tween

Use the matching [3.8 animation manual](https://docs.cocos.com/creator/3.8/manual/zh/animation/index.html), [tween manual](https://docs.cocos.com/creator/3.8/manual/zh/tween/index.html) and [tween interface](https://docs.cocos.com/creator/3.8/manual/zh/tween/tween-interface.html) for public behavior. Read the [independent architecture note](../../../3.x/08-animation-and-effects.md) before the [comparison](../../../comparisons/08-animation-and-effects.md).

1. Identify an ordinary `AnimationClip`/`AnimationState`, `SkeletalAnimation`, `AnimationController` graph, or `tween` chain. Record component enabled state, clip name, `playOnLoad`, cross-fade duration, wrap mode and the target property. For `SkeletalAnimation`, record `useBakedAnimation` and whether the target is a bone node, skinned mesh, or Socket. Keep [experimental procedural animation](https://docs.cocos.com/creator/3.8/manual/zh/animation/marionette/procedural-animation/index.html) on its own path: `AnimationController.update` evaluates its graph during component update, while the ordinary AnimationManager runs later as a system.
2. For ordinary clips, follow `AnimationComponent.play/crossFade → CrossFade → AnimationManager.update`. The manager updates fades and states, applies the blend buffer, then flushes delayed events. For baked skeletal clips, follow `SkeletalAnimation.doPlayOrCrossFade → SkeletalAnimationState._sampleCurvesBaked → SkinnedMeshRenderer → BakedSkinningModel`. Check that `skinningRoot` is an ancestor of the renderer and has an enabled `SkeletalAnimation`; otherwise `_tryBindAnimation` cannot register the renderer. Distinguish the state's `IAnimInfo.data[0]` frame index, the model's joint texture and per-frame bounds, and Socket target transforms. A moving mesh does not imply CPU bone-node transforms change. The sample `soldier.prefab` has `Take 001.animation` wired with baked `playOnLoad=true`; [two Web snapshots](../../traces/3.8.7-stage8-skeletal-web.jsonl) confirm its playing state, changing baked frame and four associated `BakedSkinningModel` renderers. Socket movement and events remain untested.
3. For tweens, follow `cocos/tween/tween.ts::start → _unionForStart → TweenSystem` and its ActionManager. `pause/resume` set the individual final Action's pause flag; `stop` stops and removes it. `Director.tick` updates components first, then `AnimationManager` at HIGH priority and `TweenSystem` at MEDIUM priority, then components' `lateUpdate`.
4. If both paths write one property, measure values at the same frame boundaries. The [fixed-clock Web trace](../../traces/3.8.7-stage8-clip-tween-headless-web.jsonl) shows AnimationManager writing `position.x=20` before TweenSystem writes 40 on the first nonzero shared-property step; Tween wins the final sample at 200. This does not establish natural-frame rendering or different blend weights. Do not apply 2.4 `cc.Action` usage to this path.
   The [temporary 3.8 clip/tween probe](../../probes/stage8-clip-tween-3.8.js) uses the official `animation.VectorTrack` path for an in-memory test. The Web preview's legacy `cc` global lacks `cc.animation.VectorTrack`, so the probe imports the formal `cc` module through SystemJS; that import and the fixed-clock probe have run successfully in the current Web preview. Treat animation timeline function events separately from component playback events: `EventEvaluator` can call an event directly on its first sample, while later crossed keys queue it through AnimationManager.
5. Record Creator patch version, Web/Native platform, time scale, pause state, frame values and delayed event order. The [3.8 Web fixed-clock trace](../../traces/3.8.7-stage8-tween-web.jsonl) confirms AnimationManager before TweenSystem and one Tween's pause/resume/stop values under manual `Director.tick(0.05)`; it does not cover natural RAF, `by`, or multiple Tweens on one target; ordinary clip and shared-property behavior are covered by the separate trace above. The [stage 8 validation record](../animation-effects-validation.md) tracks remaining observations.

When diagnosing baked resources, inspect `JointTexturePool.getSequencePoseTexture/releaseHandle` separately from Asset reference counts: the texture handle is released only when its count reaches zero after being marked for deletion by clip or Skeleton release. Treat this as a source path until a real scene-switch trace confirms timing.

For audio, distinguish async `AudioPlayer.load` and obsolete clip results; for particles distinguish `ParticleSystem` from `ParticleSystem2D`. Follow their dedicated source paths in the architecture note.
