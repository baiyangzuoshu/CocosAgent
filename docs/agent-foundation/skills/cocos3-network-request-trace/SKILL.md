# Trace 3.8.7 network requests

Use for a 3.8.7 business request or connection failure. Start with the [HTTP manual](https://docs.cocos.com/creator/3.8/manual/zh/advanced-topics/http.html), [WebSocket manual](https://docs.cocos.com/creator/3.8/manual/zh/advanced-topics/websocket.html), [source map](../../../3.x/11-auxiliary-capabilities.md), and [validation record](../auxiliary-capabilities-validation.md).

1. Record target, preview or published build, engine provenance, URL/method, and whether the caller is `fetch`, global `XMLHttpRequest`, `WebSocket`, or resource `assetManager`.
2. On Native, follow `platforms/native/builtin/index.js` for `jsb.XMLHttpRequest/WebSocket` and `jsb-adapter/window.js → fetch.js::fetch → XMLHttpRequest`. The XHR binding is in `native/cocos/bindings/manual/jsb_xmlhttprequest.cpp`; Web and mini-game targets use different providers. The adjacent source path must be checked against the package's actual engine before attributing its runtime behavior.
3. For HTTP, record status and body as well as callback/promise outcome. The [Mac HTTP trace](../../traces/3.8.7-stage11-mac-native-http.jsonl) shows XHR `onload` and `fetch` resolution for both 200 and 503, with `fetch.polyfill=true`; check `response.ok` or `status` in game code. A separate [connection-refused trace](../../traces/3.8.7-stage11-mac-native-connection-refused.jsonl) twice showed XHR `onerror`/status 0 and `fetch` rejection. This is one local transport failure, not a rule for TLS or other hosts.
4. `cocos/asset/asset-manager/downloader.ts::downloadFile` is an engine-internal resource path in 3.8.7. Trace asset download and cache errors separately from a business `fetch` call. For WebSocket, inspect the global `WebSocket` and native binding separately, then record `open/message/error/close`, payload, code and `wasClean` when present. The [Mac text echo](../../traces/3.8.7-stage11-mac-native-websocket.jsonl) confirms clean close. A [binary echo](../../traces/3.8.7-stage11-mac-native-websocket-binary.jsonl) confirms `ArrayBuffer` and five preserved bytes after explicitly setting `binaryType='arraybuffer'`, consistent with `jsb_websocket.cpp::webSocketSend` and `JsbWebSocketDelegate::onMessage`; default type and large messages remain untested. The client read `readyState=2` and `3` inside normal `onclose` in different runs; do not use a fixed readyState as the callback's precondition on this package. A [TCP reset after open](../../traces/3.8.7-stage11-mac-native-websocket-abrupt.jsonl) produced only `onclose` with `code=1001/wasClean=false`; a [403 handshake rejection](../../traces/3.8.7-stage11-mac-native-websocket-rejected-handshake.jsonl) produced `onerror → onclose` without `onopen`, though its close event had `code=0/wasClean=true`. Record whether `open` occurred and keep the server-side response; neither `onerror` nor `wasClean` alone identifies the outcome. `wss://` needs separate tests.
5. Reproduce in the affected target with a controlled endpoint and report the observable outcome, selected adapter/binding, package provenance, and untested platform conditions.

The [Mac HTTP probe](../../probes/stage11-mac-http.py), [connection-refused probe](../../probes/stage11-mac-connection-refused.py), and [WebSocket probe](../../probes/stage11-mac-websocket.py) are specific to the two local example packages and restore their generated files. The WebSocket probe has `--drop-after-text`, `--binary-echo`, and `--reject-handshake` modes. They do not validate Web, mini-game, TLS, larger/fragmented frames, or other handshake failures.
