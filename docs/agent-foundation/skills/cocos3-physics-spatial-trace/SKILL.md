# Trace 3.8.7 physics and spatial behavior

Start with the matching [3.8 2D physics manual](https://docs.cocos.com/creator/3.8/manual/zh/physics-2d/physics-2d.html) or [3D physics manual](https://docs.cocos.com/creator/3.8/manual/zh/physics/index.html), then the [3.x source map](../../../3.x/09-physics-and-spatial.md). Keep backend-specific facts and preview evidence separate.

1. Identify `PhysicsSystem2D` versus 3D `PhysicsSystem`, then inspect the project feature selection, selected backend ID, system registration and actual World separately. Backends register at `Game.EVENT_PRE_SUBSYSTEM_INIT`; systems register after Director init, with optional manual WASM loading. 2D Builtin and Box2D differ; 3D Builtin, Cannon, Bullet and PhysX differ. A backend directory or `PHYSICS_*` flag alone does not prove the preview World exists. Check `PhysicsSystem2D.PHYSICS_NONE` before its lazy `.instance`; 3D `.instance` may be absent when disabled or awaiting manual load. The 2D flags omit `box2d-jsb`, so all three named backend flags can be false while a native backend exists; check selector ID and World in that case. Do not call `selector.switchTo` just to identify a backend: 3.8.7 2D switching does not destroy the old World.
2. For step timing, follow `Director.tick → components/update → components/lateUpdate → deferredDestroy → systems/postUpdate`. In 2D, trace `syncSceneToPhysics → fixed-step loop → delayed events → syncPhysicsToScene`; in 3D, trace each substep's `syncSceneToPhysics → step → emitEvents → syncAfterEvents`. Record `autoSimulation`, step size, accumulator and max substeps.
3. For 2D contact, check Collider2D or system `Contact2DType` subscriptions. The TypeScript Box2D, Box2D WASM, and Box2D JSB wrappers register a fixture for contact reporting only if its RigidBody2D listener is enabled when the fixture is created; their contact emission again requires at least one `enabledContactListener` for a system-level event. A late property change alone may leave the fixture unregistered. The [TypeScript Box2D Web isolation trace](../../traces/3.8.7-stage9-2d-listener-apply-headless-web.jsonl) shows that, after initial node transform flags clear, only changing the field leaves registration at zero and yields no Begin; calling `Collider2D.apply()` recreates and registers the fixture, then Collider and system receive Begin. Check for pending scale changes, because `syncSceneToPhysics` can implicitly call `apply()` and confound a field-only test. This has not been run on WASM, JSB, or native. Builtin needs colliders, checks both collision-matrix directions, sends only BEGIN/END and passes no contact object. Removal or group change while touching can dispatch END immediately. For 3D, subscribe on Collider with `onTrigger…`/`onCollision…`, check trigger/collision rules for the selected backend, and inspect its event generation. The 3.8 manual requires at least one `isTrigger` Collider for triggers; on non-Builtin it also requires a non-static rigid body. Its collision section and body-type table allow a non-static body, while a later summary says a Dynamic body is required; the [current Bullet Web trace](../../traces/3.8.7-stage9-3d-events-headless-web.jsonl) confirms Kinematic/Static non-trigger collision Enter, supporting the non-static wording for that backend; verify other backends separately. Builtin Collider source says all colliders effectively behave as triggers and its Shape setter does not apply `isTrigger`; this remains a source-only finding until preview verification. `Collider.on/off` updates event-demand flags; Cannon reuses its event/contact objects. Do not infer rigid-body collision events from Builtin.
4. For 2D queries, use world coordinates. `PhysicsSystem2D.testPoint` returns an array in 3.8.7 source and API reference, despite singular wording in the 3.8 manual; Builtin and all three Box2D wrappers reuse their `testPoint/testAABB` result array, so copy it before another query. Builtin `raycast` returns `[]`; inspect Box2D for ray hits. Confirm the actual backend and platform before treating source behavior as observed.
5. For 3D ray queries, build a world ray (from a Camera when starting at a screen point), call `PhysicsSystem.raycast/raycastClosest`, and copy needed result values before the next query. 3D Builtin does raycast despite 2D Builtin returning `[]`; its current implementation ignores `queryTrigger` and passes a zero hit normal. A visible model without a physics Collider is not a physical hit target.
6. For 3D `sweepBox/Sphere/Capsule`, check the active backend before interpreting `false`: Builtin and Cannon World methods warn and return `false` in 3.8.7, whereas Bullet and PhysX have implementations. For 3D events, follow Cannon, Bullet, or PhysX separately; Bullet gathers contacts conditionally and PhysX buffers native callbacks.
7. Validate one minimal contact and query case per relevant backend in the 3.8 preview before asserting natural callback order, pose synchronization or platform parity. The [2D query probe](../../probes/stage9-2d-query-contact-3.8.js) has a [TypeScript Box2D Web trace](../../traces/3.8.7-stage9-2d-query-web.jsonl) validating an array return and result reuse. Its earlier empty contact list used Colliders without RigidBody2D. A separate [contact-listener probe](../../probes/stage9-2d-contact-listener-3.8.js) and [Web trace](../../traces/3.8.7-stage9-2d-contact-web.jsonl) validate the listener gate for isolated Dynamic sensor pairs under paused-game direct Box2D stepping. The [backend snapshot](../../traces/stage9-backend-web.jsonl) shows BulletWorld for 3D; a [temporary ray probe](../../probes/stage9-3d-raycast-3.8.js) and [Web trace](../../traces/stage9-3d-ray-web.jsonl) validate one hit and one miss on that backend. The [Bullet event probe](../../probes/stage9-3d-events-bullet-3.8.js) has a [natural-frame Web trace](../../traces/3.8.7-stage9-3d-events-headless-web.jsonl): 24 `AFTER_PHYSICS` frames, no static/Static trigger Enter, Dynamic trigger Enter on both sides, and Dynamic/Static plus Kinematic/Static non-trigger collision Enter on both sides with four contacts each. The [Builtin event probe](../../probes/stage9-3d-builtin-events-3.8.js) compares three overlap combinations but requires an actual `BuiltinWorld`; it has no runtime trace. The [2D natural-frame trace](../../traces/3.8.7-stage9-2d-natural-frame-headless-web.jsonl) places Box2D Begin after `AFTER_UPDATE`, between 2D `BEFORE_PHYSICS` and `AFTER_PHYSICS`. This scene also runs the 3D Bullet system, which emits a second pair of the same Director event names; the probe wraps each system only while observing to label their origin. `maxSubSteps=1` here, so two Physics marker pairs do not mean two Box2D substeps. A separate [moving-body probe](../../probes/stage9-moving-sync-2d-3.8.js) and [Web trace](../../traces/3.8.7-stage9-2d-moving-sync-headless-web.jsonl) show that this current TypeScript Box2D preview reads the old position in same-frame `update/lateUpdate` and initial-overlap Begin; 2D `AFTER_PHYSICS` reads the synced position and the next component `update` sees it. The initial-overlap contact does not establish every later collision callback position. 3D Builtin/Cannon/PhysX and native platforms remain untested.
