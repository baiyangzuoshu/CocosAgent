# Trace 2.4.15 audio

Use the [2.4 audio playback manual](https://docs.cocos.com/creator/2.4/manual/zh/audio/audio.html) and [AudioSource manual](https://docs.cocos.com/creator/2.4/manual/zh/components/audiosource.html) for public behavior. Read the [2.4 source map](../../../2.x/08-animation-and-effects.md) before the [version comparison](../../../comparisons/08-animation-and-effects.md).

1. Identify the actual playback owner: `cc.AudioSource` component or `cc.audioEngine` ID. Record the `AudioClip`, its load mode, node active state, `playOnLoad`, `preload`, loop setting, platform and user gesture. `cc.audioEngine.play` takes a complete `AudioClip`, and its instances are managed by ID.
2. For a component, trace `CCAudioSource.clip/onLoad/onEnable/play/onDisable/onDestroy → CCAudio.src/play/stop`. Clip replacement stops the old instance; `CCAudio.src` ignores a stale old clip load callback. `play` seeks to zero before starting; disabling the component invokes `stop`, while a game hide event may invoke `pause` and show may resume.
3. For a global instance, trace `CCAudioEngine.play → getAudioFromPath → CCAudio`; track the returned ID through `stop` or `uncache`. `getAudioFromPath` groups IDs by `clip.nativeUrl` and stops the oldest for that URL once its list reaches 24. This is a per-URL limit for `cc.audioEngine` in this source snapshot; `CCAudioSource` does not use it. `getMaxAudioInstance` reads 24, while deprecated `setMaxAudioInstance` does not change it. The separate 32-object pool is for recycling, not a playback limit. Stopping an `AudioSource` does not identify or manage unrelated `cc.audioEngine` IDs.
4. At the platform boundary, inspect `CCAudio._createElement` for DOM/WebAudio selection and `_touchToPlay` for browser gesture retry. Record `_ensureLoaded` completion, `play`/`stop`, current time, state and audible result separately. Do not infer audible playback from a successful API call.
   For scene switches, inspect `CCAudioClip.destroy → cc.audioEngine.uncache` and the old scene's auto-release decision before predicting whether a global playback ID survives. Component `onDisable/onDestroy` is a separate stop/destroy path. For game pause, `cc.game.pause/resume` calls `_break/_restore` for engine IDs; component audio uses its `EVENT_HIDE/SHOW` listeners.
5. Use real imported short clips in Creator 2.4.15. The demo contains `assets/resources/stage8-tone-a/b.wav` with Creator-generated `audio-clip` `.meta`; confirm runtime loading before using the [concurrency probe](../../probes/stage8-audio-2.4.js). Its [Web trace](../../traces/2.4.15-stage8-audio-web.jsonl) shows same-URL ID 1 displaced by ID 25, while 25 mixed-URL IDs stayed managed at sampling time. The [component lifecycle probe](../../probes/stage8-audio-lifecycle-2.4.js) and [trace](../../traces/2.4.15-stage8-audio-lifecycle-headless-web.jsonl) show natural `ended`, stop on disable, and a separate global ID surviving component destruction. The [disk-scene probe](../../probes/stage8-audio-scene-2.4.js) has independent [autoRelease=false](../../traces/2.4.15-stage8-audio-scene-keep-headless-web.jsonl) and [true](../../traces/2.4.15-stage8-audio-scene-release-headless-web.jsonl) traces: this dynamically loaded Clip remains cached after either switch; explicit `releaseAsset` triggers `uncache` and stops the global ID. It is not a serialized scene dependency. The [audio harness](../../probes/creator-audio-headless-probe.mjs) relaxes Chrome's first-gesture policy, so default autoplay and audible output are untested. Native, background interruption, editor-imported static scene dependencies and slow loading still need separate evidence; see the [validation record](../animation-effects-validation.md).
6. Before diagnosing static scene release, confirm that the Creator-imported Scene actually resolves `AudioSource.clip`, that `dependUtil.getDeps(scene._id)` includes the Clip UUID, and that the loaded Clip has a scene ownership reference. If the source `.fire` and imported cache disagree, use the [official AssetDB refresh API](https://docs.cocos.com/creator/2.4/manual/zh/extension/asset-management) before interpreting preview behavior. The [stale-import trace](../../traces/2.4.15-stage8-audio-static-scene-stale-import-headless-web.jsonl) has no Clip/dependency and is not a release result. A separate [in-memory dependency probe](../../probes/stage8-audio-injected-scene-dependency-2.4.js) and [Web trace](../../traces/2.4.15-stage8-audio-injected-scene-dependency-headless-web.jsonl) show the actual `Director → releaseManager` branch once a Clip UUID and one ownership reference are registered: both switches reduce refCount from 1 to 0; with `autoReleaseAssets=false` Clip/cache and independent ID remain, while true destroys Clip and `uncache` stops the ID. This tests the release path under constructed dependencies, not Creator's import of the scene file.
