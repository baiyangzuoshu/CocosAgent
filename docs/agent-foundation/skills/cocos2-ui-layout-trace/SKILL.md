# Trace 2.4.15 UI layout and interaction

Confirm Creator 2.4. Read the matching [2.4 UI manual](https://docs.cocos.com/creator/2.4/manual/zh/ui/index.html) page for Canvas, Widget, Layout, Label, Button or ScrollView; ScrollView's View/Content/Mask guidance is in the [ScrollView manual](https://docs.cocos.com/creator/2.4/manual/zh/components/scrollview.html). Use the [2.x architecture note](../../../2.x/07-ui-system.md).

1. Record design resolution, actual frame/visible size, Canvas fitWidth/fitHeight, Camera, and the target Node's contentSize/anchor. Follow `CCCanvas.applySettings → CCView.setDesignResolutionSize` before attributing positions to Widget.
2. For a misplaced element, inspect Widget alignment target, edge/center flags, offsets and alignMode. Follow `CCWidgetManager` resize and `EVENT_AFTER_UPDATE`; Web runtime listens to `canvas-resize`, not directly to `design-resolution-changed`. In the measured direct `cc.view.setDesignResolutionSize(1280,720,SHOW_ALL)` case, View scale/visibleSize changed while the Canvas and background Widget stayed 960×640 through the next `AFTER_UPDATE`. Reproduce a real window/Canvas resize separately; use public `widget.updateAlignment()` when the caller needs the current-frame value.
3. For a dynamic list, inspect Layout type, Resize Mode, spacing/padding, child active state and Node size. `CCLayout` listens to child changes and normally updates after `EVENT_AFTER_UPDATE`. Use `updateLayout()` when computing an immediate content size or ScrollView boundary; it skips layout when no child is active. In the measured 260×54-item case, clearing the four-item list leaves the CONTAINER at 300×266 and `_layoutDirty=true`, even after `updateLayout()`; see the [runtime trace](../../traces/2.4.15-ui-system.jsonl).
4. For text-induced movement, inspect `CCLabel.string`, font, Overflow, Label size and the parent Layout's dirty state. For a missing click, follow Node hit testing and propagation from the [2.x input note](../../../2.x/05-input-and-events.md), then `CCButton._onTouchBegan/_onTouchEnded`, `clickEvents` and node `click`.
5. For scrolling, verify View/Content/Mask, ScrollView references, Content size and any Layout; `_calculateBoundary()` synchronously updates enabled Content Layout. Trace capture-phase touch, nested ViewGroup, `_touchMoved` and `cancelInnerEvents`: source compares `getLocation() - getStartLocation()` to 7 coordinate units, without DPI adjustment, and simulates child `TOUCH_CANCEL` once past the threshold. `_handleMoveLogic()` moves Content within MOVE; `update(dt)` advances auto-scroll. Measure tap, drag and wheel separately, logging child touch/click, Content position, ScrollView events and ScrollBar state. In the [Web trace](../../traces/2.4.15-scrollview-web.jsonl), a 4-pixel MOVE scrolls Content before the child MOVE callback, 14 pixels simulates CANCEL, and a tap still clicks Button. Wheel movement is synchronous, with platform-specific source coefficients. Its timeout sends `scroll-ended` but leaves `_scrolling=true`; a following drag may lack `scroll-began` until release resets it. Do not infer other DPI/platform thresholds, inertia or ScrollBar behavior from this probe.
6. For code subscriptions, use string names such as `node.on('scroll-began', ...)`. `cc.ScrollView.EventType` contains numeric values for the component's editor `scrollEvents` mapping and is not the Node event name. Record which route generated each callback.

Read the [same-behavior comparison](../../../comparisons/07-ui-system.md) only after establishing the 2.4 path. The [validation note](../ui-system-validation.md) tracks observed and pending cases.
