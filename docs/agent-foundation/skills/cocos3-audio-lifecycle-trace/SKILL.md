# Trace 3.8.7 audio

Use the [3.8 AudioSource manual](https://docs.cocos.com/creator/3.8/manual/zh/audio-system/audiosource.html) for public behavior. Read the [3.8 source map](../../../3.x/08-animation-and-effects.md) before the [version comparison](../../../comparisons/08-animation-and-effects.md). The 2.x public `cc.audioEngine` API is absent in 3.x.

1. Identify normal `AudioSource.play` versus `playOneShot`. Record `AudioClip`, `loadMode`, node active state, `playOnAwake`, platform, user gesture and whether the node is persistent. `playOneShot` creates separate playback that the component cannot later pause or stop, and it does not emit the component's `ENDED` event.
2. Trace `AudioSource.clip → _syncPlayer → AudioPlayer.load → _syncStates`. Check queued `play/pause/stop/seek` operations while loading. When a clip changes, a late old player is destroyed; after load, `_resetPlayer` disposes the previous player and synchronizes loop, volume and queued operations.
3. Trace normal `play` Promise completion to `STARTED`, player completion to `ENDED`, and interruption callbacks separately. `onDisable` pauses ordinary nodes but returns for a persistent root; `onDestroy` stops and clears the clip. `playOneShot` finishes loading asynchronously and then starts a manager-owned one-shot; its Promise continuation lacks the ordinary `_syncPlayer` clip/stale-player check. A controlled WebAudio successful-load trace below starts after its source node was destroyed. These control operations and actual audible output are separate observations.
4. At the platform boundary, inspect `pal/audio/web/player.ts` for DOM/WebAudio selection or `pal/audio/native/player.ts` for native preload and URL reference counting. Native `AudioPlayer.destroy` calls `uncache(url)` when that URL's player count reaches zero; `stop()` itself is not that release path. Keep `AudioClip`'s own player distinct from the component player.
   For scene switches, record normal `AudioSource.onDestroy → stop; clip=null`, `AudioClip.destroy` of its own `_player`, and the independent one-shot registered with `AudioManager`. A one-shot may outlive its source node, but resource release and backend behavior must be measured. `game.pause/resume` events are listened to by ordinary Web/Native players; do not assume `AudioManager.pause` is called or that one-shots have the same interruption path.
5. Trace `AudioManager.discardOnePlayingIfNeeded`: normal and one-shot players share the backend channel limit; when full, it discards the oldest one-shot first, otherwise the oldest normal player. `AudioSource.maxAudioChannel` reflects the backend (Web 24, minigame 10, native runtime query in this snapshot). The demo contains `assets/resources/stage8-tone-a/b.wav` with Creator-generated `audio-clip` `.meta`. The [concurrency probe](../../probes/stage8-audio-3.8.js) and [trace](../../traces/3.8.7-stage8-audio-web.jsonl) show adding one-shot after 24 ordinary players stopped player 0. The [WebAudio eviction probe](../../probes/stage8-audio-oneshot-eviction-3.8.js) directly records the reverse order: after 23 ordinary and one one-shot sources, starting the last ordinary source stops the one-shot first; see its [trace](../../traces/3.8.7-stage8-audio-oneshot-eviction-headless-web.jsonl). The [component lifecycle probe](../../probes/stage8-audio-lifecycle-3.8.js) and [trace](../../traces/3.8.7-stage8-audio-lifecycle-headless-web.jsonl) show `STARTED/ENDED`, pause on disable, and stop/clip clearing on destruction. `ENDED` callback samples state PLAYING before it later becomes INIT. The [disk-scene probe](../../probes/stage8-audio-scene-3.8.js) has [autoRelease=false](../../traces/3.8.7-stage8-audio-scene-keep-headless-web.jsonl) and [true](../../traces/3.8.7-stage8-audio-scene-release-headless-web.jsonl) traces: this dynamically loaded Clip stays cached until explicit release. A distinct [static-scene probe](../../probes/stage8-audio-static-scene-3.8.js) uses a serialized `AudioSource._clip`; its [trace](../../traces/3.8.7-stage8-audio-static-scene-headless-web.jsonl) confirms the Clip in Scene dependencies with `refCount=1`, falling to 0 at scene switch. With `autoReleaseAssets=true` the Clip is destroyed next frame; with false it stays cached. Record dependency membership and reference count before interpreting release behavior. The [one-shot scene probe](../../probes/stage8-audio-oneshot-backend-3.8.js) records a source surviving scene switch and Clip release without a stop call, then ending naturally in its [trace](../../traces/3.8.7-stage8-audio-oneshot-backend-headless-web.jsonl). The [slow-load probe](../../probes/stage8-audio-oneshot-slow-load-3.8.js) delays one XHR, destroys the source node, then allows loading; its [trace](../../traces/3.8.7-stage8-audio-oneshot-slow-load-headless-web.jsonl) records backend start after destruction. These backend observations are not public completion events or audible proof. The [audio harness](../../probes/creator-audio-headless-probe.mjs) relaxes Chrome's first-gesture policy. Verify default autoplay, Native/DOM Audio, other slow-load results and background interruption separately; see the [validation record](../animation-effects-validation.md).
