# Trace 2.4.15 physics and spatial behavior

Use the matching [2.4 physics manual](https://docs.cocos.com/creator/2.4/manual/zh/physics/index.html) or [3D physics manual](https://docs.cocos.com/creator/2.4/manual/zh/physics-3d/physics-manager.html) as the public contract, then follow the [2.x source map](../../../2.x/09-physics-and-spatial.md). Keep source deductions separate from preview observations.

1. Identify the actual route: plain `cc.Collider` + `getCollisionManager`, `cc.PhysicsCollider/RigidBody` + `getPhysicsManager` (Box2D), or 3D Collider/RigidBody + `getPhysics3DManager`. Check that the manager exists and is enabled before interpreting missing events.
2. For simple 2D collision, inspect `CCCollider.onEnable → CCCollisionManager.addCollider → update → CCContact.updateState → _doCollide` and callbacks `onCollisionEnter/Stay/Exit(other,self)` on node components. Check the one-direction `cc.game.collisionMatrix` lookup, world shape and immediate Exit on removal or group change. Do not expect Box2D forces or `PhysicsContact`.
3. For 2D Box2D, inspect `CCPhysicsManager.update → World.Step → CCPhysicsContact.emit → _syncNode`. Check `enabledContactListener`, `enabledAccumulator`, project frame rate and `rayCast` type. In this snapshot fixture creation registers contact reporting only if its RigidBody listener is already enabled; `CCPhysicsContact.emit` again checks the current flag before calling node components. Verify listener state before fixture creation when debugging a missing callback. In the [current Box2D Web isolation trace](../../traces/2.4.15-stage9-2d-listener-reenable-headless-web.jsonl), changing the field after creation leaves the fixture unregistered and produces no Begin; disabling then enabling its `PhysicsBoxCollider` recreates and registers the fixture and produces Begin. This is a paused-game direct-step observation, not a native or natural-frame timing guarantee. `testPoint(worldPoint)` returns one Collider or null; `testAABB` returns an array. Their shared AABB callback filters to Dynamic bodies; a ready Static fixture can still yield no query hit. Contact data is valid only for the callback unless copied.
4. For 3D, first check the `CC_PHYSICS_CANNON/BUILTIN` build macro, `cc.Physics3DManager` presence and enabled state, and actual World. The matching `instantiate.ts` binds backend constructors under its macro; Director only creates the manager when a backend module is present. Inspect `Physics3DManager.update` and the active World for synchronization. In Creator 2.4 preview the manual specifies Cannon; built project selection may differ. Subscribe to the manual's hyphenated `trigger-enter`/`collision-enter` names on `Collider3D`; the components are named `cc.RigidBody3D` and `cc.BoxCollider3D`. `RigidBody3D` has no `type` property like 3.8: its Cannon wrapper maps zero mass to Static and positive mass plus `isKinematic` to Kinematic or Dynamic. This Cannon snapshot also emits `onTrigger…`/`onCollision…` compatibility names, while Builtin emits only hyphenated trigger names. Builtin has trigger detection, not rigid-body dynamics, but does implement 3D raycast; it uses the query group matrix and ignores `queryTrigger` in this snapshot. The Collider source documents that Builtin always behaves as a trigger; its Shape `isTrigger` setter is empty. Keep this as a source observation until verified in a Builtin preview. The [Builtin event probe](../../probes/stage9-3d-builtin-events-2.4.js) compares collider-collider, trigger-collider and trigger-trigger overlaps and must only run when the actual World is `BuiltinWorld`. Copy Cannon event/contact values if retaining them. Distinguish `getPhysics3DManager().raycast` from `cc.geomUtils.intersect` on render geometry.
5. The [2.4 2D query trace](../../traces/2.4.15-stage9-2d-query-web.jsonl) validates manual simple-collision Enter/Stay/Exit and Dynamic-sensor queries. The [Box2D contact trace](../../traces/2.4.15-stage9-2d-contact-web.jsonl) tests fixtures created with listeners off, on before creation, and enabled only after creation: late enabling does not register the fixture; an already registered pair receives Begin and End on the listening side. Both traces use manual manager updates, not natural frame scheduling. The [backend snapshot](../../traces/stage9-backend-web.jsonl) shows a CannonWorld with its manager initially disabled. The [temporary 3D ray probe](../../probes/stage9-3d-raycast-2.4.js) enables that manager for one same-shape ray experiment, then restores the prior state; its [Web trace](../../traces/stage9-3d-ray-web.jsonl) records a hit at distance 9 and an offset miss. The [Cannon event probe](../../probes/stage9-3d-events-cannon-2.4.js) has a [natural-frame Web trace](../../traces/2.4.15-stage9-3d-events-headless-web.jsonl): static and Dynamic trigger pairs send trigger Enter on both sides; Dynamic/Static non-trigger sends collision Enter with four contacts; Kinematic/Static non-trigger (mass 10, Cannon body type 4) sends **trigger Enter**, because this snapshot's `external/cannon/cannon.js::Narrowphase.getContacts` marks that body-type pair `justTest`. Both manual hyphenated and Cannon compatibility event names fired. The manager was enabled only for the probe and restored after 27 `AFTER_PHYSICS` frames. The [Builtin event probe](../../probes/stage9-3d-builtin-events-2.4.js) still needs an actual Builtin World. The [2D natural-frame trace](../../traces/2.4.15-stage9-2d-natural-frame-headless-web.jsonl) places Box2D Begin on both sensor sides between Director `BEFORE_UPDATE` and `AFTER_UPDATE` in the same frame, with the manager temporarily enabled. A separate [moving-body probe](../../probes/stage9-moving-sync-2d-2.4.js) and [Web trace](../../traces/2.4.15-stage9-2d-moving-sync-headless-web.jsonl) show this current Box2D preview reads the old position in component `update` and initial-overlap Begin, then the synced position in same-frame `lateUpdate`. The initial-overlap contact does not establish every later collision callback position. Consult the [stage 9 validation record](../physics-spatial-validation.md) before claiming other backends or platform parity.
