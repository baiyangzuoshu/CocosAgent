# Trace 2.4.15 network requests

Use for a 2.4.15 game request that fails, returns an unexpected response, or differs from resource loading. Start with the [2.4 network manual](https://docs.cocos.com/creator/2.4/manual/zh/scripting/network.html), [source map](../../../2.x/11-auxiliary-capabilities.md), and [validation record](../auxiliary-capabilities-validation.md).

1. Record Creator version, target platform, preview or published build, request URL/method, and whether the caller is game code or `cc.assetManager`. Game scripts use global `XMLHttpRequest`/`WebSocket`; `cocos2d/core/asset-manager/download-file.js` creates its own XHR and adds resource-pipeline completion rules.
2. For XHR, record `readyState`, `status`, `onload/onerror/ontimeout/onabort`, and response type/body. Treat `onload` as a completed HTTP response; check status before treating it as success. The [Mac HTTP trace](../../traces/2.4.15-stage11-mac-native-http.jsonl) shows `onload` for both 200 and 503. A separate [connection-refused trace](../../traces/2.4.15-stage11-mac-native-connection-refused.jsonl) twice reached `ontimeout` at a 4-second setting with `status=0`, rather than `onerror`. Keep both callbacks in diagnostics; other failure modes and platforms need separate tests.
3. For WebSocket on native, confirm the project's Native Socket module is enabled as the manual requires. Use the global `WebSocket` entry, then record `open/message/error/close`, payload and the actual close fields. The [Mac text echo](../../traces/2.4.15-stage11-mac-native-websocket.jsonl) confirms global `WebSocket` works while `jsb.WebSocket` is undefined; do not require the latter when diagnosing 2.4. A [binary echo](../../traces/2.4.15-stage11-mac-native-websocket-binary.jsonl) shows `ArrayBuffer` and five preserved bytes when `binaryType='arraybuffer'` is set; do not infer the default binary type or large-message behavior. The close callback did not expose `code/wasClean` in this package, and its immediate `readyState` varied between normal-close runs. A [TCP reset after open](../../traces/2.4.15-stage11-mac-native-websocket-abrupt.jsonl) reached `onclose` without `onerror`, while a [403 handshake rejection](../../traces/2.4.15-stage11-mac-native-websocket-rejected-handshake.jsonl) reached `onerror → onclose` without `onopen`. Record all three events and the server-side handshake response; other failure modes need separate tests.
4. The adjacent 2.4 engine directory lacks the native XHR/WebSocket C++ binding. Stop the source chain at the host API, and inspect the actual package or Creator installation before claiming a native internal mechanism.
5. Reproduce with a controlled endpoint where possible, label the result by target and build, and keep business network errors separate from `cc.assetManager` download/cache errors.

The [Mac HTTP probe](../../probes/stage11-mac-http.py), [connection-refused probe](../../probes/stage11-mac-connection-refused.py), and [WebSocket probe](../../probes/stage11-mac-websocket.py) temporarily edit generated scripts for the two exact example packages and restore their bytes. The WebSocket probe has `--drop-after-text`, `--binary-echo`, and `--reject-handshake` modes. Use them only when those paths match; they do not test TLS, larger/fragmented frames, other handshake failures, or external networks.
