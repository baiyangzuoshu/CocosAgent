# Trace 3.8.7 UI layout and interaction

Confirm Creator 3.8. Start from the relevant [3.8 UI manual](https://docs.cocos.com/creator/3.8/manual/zh/2d-object/ui-system/index.html) page, including the [ScrollView manual](https://docs.cocos.com/creator/3.8/manual/zh/ui-system/components/editor/scrollview.html), and the [3.x architecture note](../../../3.x/07-ui-system.md).

1. Check that the target lives under a live Canvas or RenderRoot2D and has the needed UITransform. Record its Node layer, Camera visibility, Camera target and actual pipeline before diagnosing layout or a missing draw. Canvas need not own the Camera that renders its children.
2. For adaptation, record project design resolution/Fit policy, `View` visibleRect/scale, Canvas UITransform dimensions, `cameraComponent` and `alignCanvasWithScreen`. Follow `View.setDesignResolutionSize`; WidgetManager listens directly to `design-resolution-changed` and marks affected widgets dirty synchronously, then aligns them during `AFTER_UPDATE`. A temporary four-edge `ON_WINDOW_RESIZE` Widget was observed to leave its Canvas at 960×640 during the setter call, then stretch to 1280×720 and move from (480,320) to (640,360) after the next `AFTER_UPDATE`; restoring the View similarly restores the Canvas on the next frame. Use `widget.updateAlignment()` if the caller needs the current-frame position.
3. For a dynamic list, inspect Layout type, Resize Mode, spacing/padding, child UITransform/active state and `_layoutDirty`. `Layout.updateLayout()` updates only when dirty unless forced; read final coordinates after `AFTER_UPDATE` or call the public method deliberately. Empty `CONTAINER` layout still enters `_doLayout()` and uses a padding/spacing formula; verify actual size before assuming zero.
4. For text movement, trace `Label.string → _markForUpdateRenderData → UITransform size events → Layout`. For a missing click, trace PointerEventDispatcher/UITransform.hitTest from the [3.x input note](../../../3.x/05-input-and-events.md), then Button press/end and `ButtonEventType.CLICK`/clickEvents. ScrollView adds capture and View/Content boundary behavior.
5. For scrolling, verify View/Content/Mask and the 3.8 manual's advice against Widget plus Layout on one Content node. `_calculateBoundary()` updates enabled Content Layout before measuring View UITransform/Content. Trace capture-phase touch, nested ViewGroup and `cancelInnerEvents`: source compares UI coordinates to 7 units, without DPI adjustment, then simulates child `TOUCH_CANCEL`. `_handleMoveLogic()` queues `_deltaAmount`; `update(dt)` moves Content and emits scroll events. Wheel also queues a fixed `-0.1` source delta; HANDLE_INPUT/GAMEPAD_INPUT is limited here to XR hover and thumbsticks. Measure tap, drag and wheel separately, logging child touch/click, Content before and after update, ScrollView events and ScrollBar state. In the [Web trace](../../traces/3.8.7-scrollview-web.jsonl), the first child MOVE sees old y=100 before scrolling to 104, 14 pixels simulates CANCEL, and a tap clicks Button. Wheel timeout emits `scroll-ended` and resets `_scrolling=false`. The temporary UI Camera must align with the design viewport and UI layer for hit testing. Do not infer other DPI/platform thresholds, inertia or ScrollBar behavior from this probe.
6. For code subscriptions, use string members such as `ScrollView.EventType.SCROLL_BEGAN` or the literal `'scroll-began'`. Internal `scrollEvents` handling maps these names to numeric editor event indices. Do not carry over the 2.4 numeric enum value into Node subscriptions.
7. Separate manual, TypeScript source and actual platform probe in the answer. The existing 3D example has no saved Canvas. Web preview measured a temporary three-item list, adding a fourth item, and empty CONTAINER height 10; UI drawing was visible over the 3D scene. A minimal Canvas/UI Camera/Button setup received Node `TOUCH_START`, `TOUCH_END`, and Button click on a physical click with either the Main Camera's default mask or a DEFAULT-only mask. Another Graphics/Label/Button probe failed twice; its configuration difference is unresolved. See the [layout trace](../../traces/3.8.7-ui-system.jsonl). A real browser window resize, ScrollBar, nested scrolling, inertia and Native gesture timing still require fresh runtime evidence.
