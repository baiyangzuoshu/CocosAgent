# Trace 3.8.7 particles

Use the [3.8 particle manual](https://docs.cocos.com/creator/3.8/manual/zh/particle-system/index.html), then the matching 2D or 3D child page. Read the [3.8 source map](../../../3.x/08-animation-and-effects.md) before the [version comparison](../../../comparisons/08-animation-and-effects.md).

1. Identify the actual component first. `ParticleSystem2D` in `cocos/particle-2d/` and 3D `ParticleSystem` in `cocos/particle/` have different simulation and render paths. Record asset/texture, emission settings, duration, active state and auto removal setting.
2. For 2D, trace `ParticleSystem2D.lateUpdate → Simulator.step → _finishedSimulation`; `stopSystem` stops emission while living particles drain, and `resetSystem` restarts. The finish condition requires no particles and `!active && !readyToPlay`, then calls `resetSystem → stopSystem → _markForUpdateRenderData` and optionally `node.destroy()` for the **whole node**. `Simulator.step` returns before this check when `renderData` is null; inspect `_flushAssembler/createData` if auto removal seems stuck. Follow `_canRender → UIRenderer.updateRenderer` and `_render → UI Batcher.commitComp` separately: `_canRender` requires `!_stopped`, but `stopSystem` does not immediately mark the renderer dirty. The previous `_renderFlag` may survive until the next dirty update, whereas an intervening dirty update may hide living particles. Continued simulation alone does not establish continued visibility; measure `particleCount`, `_stopped`, `_renderFlag`, renderData and actual frames together.
3. For 3D, trace component `play/stopEmitting/stop`, processor update and `BEFORE_COMMIT` render callback. Natural non-looping end and `stopEmitting` stop new particles; living particles drain only while the component keeps simulating. `stopEmitting` sets `_needToRestart`, so a later `play` resets timing and starts emission again; `reset` itself does not clear old particles. `stop` clears `isEmitting` and calls `clear`, whose particle removal requires `enabledInHierarchy`. Check `renderCulling` and `cullingMode`: off-screen `Pause` suspends time, simulation and drain; `PauseAndCatchup` advances `_time` without particle update; `AlwaysSimulate` continues simulation while detached from rendering. Use the [3.8 main module manual](https://docs.cocos.com/creator/3.8/manual/zh/particle-system/main-module.html) for these public modes. 3D has no 2D `autoRemoveOnFinish`. Do not apply the 3D `stop` meaning to 2D `stopSystem`.
4. The [temporary 2D four-case probe](../../probes/stage8-particle2d-3.8.js) has a [Creator Web natural-frame trace](../../traces/3.8.7-stage8-particle2d-headless-web.jsonl) and synchronized [before](../../traces/3.8.7-stage8-particle2d-headless-web-before-stop.png)/[after](../../traces/3.8.7-stage8-particle2d-headless-web-after-100ms.png) screenshots. In this in-memory opaque-white setup, `renderData` exists and living particles stay visible after `stopSystem`, even though `_canRender=false` while `_renderFlag=true`. Zero-particle and drained emitters with `autoRemoveOnFinish=true` call `node.destroy`, with default `isValid=true`, strict `isValid(node,true)=false` in that frame, then `onDestroy`. When auto removal is false, `_finishedSimulation` recurs on later frames because it resets `finished`. An actively dirtied renderer or absent `renderData` needs its own test; adjacent source-build provenance is unconfirmed. The [temporary 3D state probe](../../probes/stage8-particle3d-3.8.js) has a [direct-update Web trace](../../traces/3.8.7-stage8-particle3d-web.jsonl). The [natural-frame probe](../../probes/stage8-particle3d-natural-3.8.js) has a [Director-frame trace](../../traces/3.8.7-stage8-particle3d-natural-headless-web.jsonl) and synchronized [active](../../traces/3.8.7-stage8-particle3d-natural-headless-web-active.png)/[drained](../../traces/3.8.7-stage8-particle3d-natural-headless-web-drained.png) screenshots: temporary CPU/default particles are visibly magenta while active and absent after drain, and the model detaches by `AFTER_DRAW`. Screenshot pause enlarges the next `dt`; do not compare elapsed frame count across versions. Verify RenderCulling, imported assets, Native and GPU particles separately.
