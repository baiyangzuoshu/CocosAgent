# Place a PNG Sprite in Creator 3.8.7

Use this skill for an authorized scene edit in a Creator 3.8.7 project. The [3.8 image asset manual](https://docs.cocos.com/creator/3.8/manual/zh/asset/image.html) and [SpriteFrame manual](https://docs.cocos.com/creator/3.8/manual/zh/asset/sprite-frame.html) distinguish the imported image from its SpriteFrame subasset; the [scene editing manual](https://docs.cocos.com/creator/3.8/manual/zh/concepts/scene/scene-editing.html) describes Canvas placement for UI. This bridge's version-specific implementation is `3.8,7NewProject/extensions/cocos-agent-bridge/dist/{main,scene}.js`; the Host contract is [operation.schema.json](../../../../tools/cocos-agent-bridge/operation.schema.json).

1. Confirm the exact project path and Creator version. From the repository root, run `node tools/cocos-agent-bridge/catalog-host.js --target "3.8.7=<absolute-project-path>" --query capabilities.list --project "<absolute-project-path>" --creator-version 3.8.7`. Require the selected instance's path and `creatorVersion=3.8.7`, and `scene.pngSprite` with `contractVersion=0.1`, `access=write`, `input.required=[assetName,action]`, and `status=available`. Record the active scene and catalog revision. A scene switch or extension reload requires a fresh query; preflight will check the scene again before writing.
2. Confirm the intended `.scene` file is open. For a new local PNG, run `bridge-host.js --project "<absolute-project-path>" --creator-version 3.8.7 --png "<absolute-png-path>"` to import it. Import alone does not place it in the scene. Check the editor-generated `.meta` for a `sprite-frame` subasset; if absent, change image Type to `sprite-frame` in Creator and let the editor regenerate metadata. Do not handcraft a UUID or overwrite an existing resource. For an imported PNG, use its filename under `assets/resources/`.
3. Run `node tools/cocos-agent-bridge/bridge-host.js --project "<absolute-project-path>" --creator-version 3.8.7 --scene-asset "<filename.png>" --scene-action apply`. The 3.8 Scene Script uses a UI_2D Sprite under an existing Canvas or creates `CocosAgentCanvas` with a UI camera if none exists. The Host saves and checks the `.scene` file and a fresh scene snapshot. Capture the printed `operationId` and all `operation.receipt` lines. Verify the scene name, node name, SpriteFrame UUID, parent Canvas, and disk readback.
4. Run the Host with `--operation-get "<operationId>"` to inspect persisted phase statuses. `editor` and `disk` must be `passed` before reporting a saved edit. `preview=pending` remains pending until the actual 3.8 preview is observed for this operation; a previous demo screenshot does not establish it.
5. On timeout, disconnect, `SCENE_SAVE_UNVERIFIED`, or a crash after the write intent, use `operation.get` and inspect the saved scene before deciding on recovery. Do not rerun the same ID; the Host rejects duplicate IDs. If a reserved node has different data, stop at `SCENE_NODE_CONFLICT`. `compensate` is a new identity-checked operation and may remove the bridge-created Canvas when only its UI camera remains; verify its own disk receipt. `INVALID_SCENE_SESSION` means the loaded extension still uses an older session contract or another session was selected; reload this project's extension and refresh the catalog before another attempt.

Report the selected instance and scene, asset filename and SpriteFrame UUID, `operationId`, six phase statuses, saved-scene evidence, preview evidence or `pending`, and unresolved side effects. The [operation contract note](../../cocos-agent-operation-contract-0.1.md) distinguishes disk recovery from compensation. The independent operation ID and interruption flow passed a localhost mock. A 3.8 live attempt stopped at preflight because the loaded extension still used the old ID equality rule; no scene write occurred, and the revised extension awaits reload for real validation.
