# PNG Sprite in Creator 2.4.15

Use this skill when the user wants an authorized PNG scene edit in a Creator 2.4.15 project. The [2.4 image manual](https://docs.cocos.com/creator/2.4/manual/zh/asset-workflow/sprite.html) distinguishes the image from its SpriteFrame, and the [Canvas manual](https://docs.cocos.com/creator/2.4/manual/zh/components/canvas.html) describes the UI root. This bridge requires an existing Canvas; it does not create one. Keep the Creator 3.8 workflow separate.

From the repository root, invoke [`agent-dispatch.js`](../../../../tools/cocos-agent-bridge/agent-dispatch.js) with `--target "2.4.15=<absolute-project-path>"`, `--project "<same-path>"`, `--creator-version 2.4.15`, `--command` and JSON `--input`. Include other open projects as additional `--target` entries when relevant. The dispatcher queries `instances.list` and `capabilities.list`, selects the exact project/version, checks the instance and scene again before executing, and returns the [result envelope](../../../../tools/cocos-agent-bridge/dispatch-result.schema.json). Do not call Creator internal messages or `bridge-host.js` directly for normal skill execution.

1. Confirm the intended `.fire` scene is open. If the image is new, call `--command asset.importPng --input '{"sourcePath":"/absolute/path/image.png"}'`. Import and placement are separate operations. Require `outcome=completed`; then use the Creator-generated `assets/resources/<filename>.png.meta` SpriteFrame subasset. Do not invent a UUID or overwrite an existing resource.
2. Call `--command scene.pngSprite --input '{"assetName":"<filename.png>","action":"apply"}'`. The 2.4 implementation places the Sprite under the existing Canvas and saves the scene. If the dispatcher returns `COMMAND_UNAVAILABLE` with `CANVAS_NOT_FOUND`, open an intended scene with Canvas or stop. Require `disk=passed` before reporting a saved edit; retain `operationId`.
3. If the result is `needs-preview`, inspect the **current operation** in the local 2.4 Web preview. Once the target Sprite is visibly present, call the dispatcher with `--project`, `--creator-version 2.4.15`, `--preview-accept "<operationId>"`, and `--evidence '{"url":"<local preview URL>","observedAt":"<actual ISO time>","note":"<what was seen>"}'`. Then query `--operation-get "<operationId>"` and require `outcome=completed`, `disk=passed`, and `preview=passed`. If the image is absent, keep the operation pending and diagnose; do not record a passing visual receipt.
4. If a write returns `needs-review`, keep its ID and inspect `--operation-get` plus the scene before deciding what to do. Do not automatically resend a possibly applied write. For an authorized undo, call a **new** `scene.pngSprite` operation with `action=compensate`, then require its own `disk=passed` and `recovery=passed`. This removes only the matching Agent node. Verify the result in the current preview when visual removal matters.

Report the selected project, Creator version, scene, asset name, operation ID, outcome, phase statuses, and what was actually observed in preview. The operation record is historical: later compensation does not rewrite the original operation's passed receipts. Details and evidence limits are in the [operation contract](../../cocos-agent-operation-contract-0.1.md).
