# 同一资源行为：2.4.15 与 3.8.7

先分别阅读[2.x 独立研究](../2.x/04-assets-and-loading.md)和[3.x 独立研究](../3.x/04-assets-and-loading.md)。本表只对照游戏开发中的同一动作；术语和公开入口仍以各自[2.4 手册](https://docs.cocos.com/creator/2.4/manual/zh/asset-manager/index.html)、[3.8 手册](https://docs.cocos.com/creator/3.8/manual/zh/asset/asset-manager.html)为准。源码证据来自本地 2.4.15 JavaScript 与 3.8.7 TypeScript，Chrome 预览生命周期观测分别见[2.x](../agent-foundation/traces/2.4.15-asset-lifecycle.jsonl)和[3.x](../agent-foundation/traces/3.8.7-asset-lifecycle.jsonl)；磁盘/编辑器/原生分面结果见[验证矩阵](../agent-foundation/asset-validation-matrix.md)。

| 开发行为 | 2.4.15 | 3.8.7 | 对诊断的影响 |
| --- | --- | --- | --- |
| 在编辑器导入源资源并被场景引用 | 源文件旁 `.meta` 记录 UUID、导入设置及 `subMetas`。示例 `HelloWorld.png.meta` 的 SpriteFrame 有独立 UUID；`.fire` 引用 SpriteFrame UUID，子资源再关联主贴图 UUID。 | `.meta` 同样维护身份和设置；示例 `soldier.FBX.meta` 的 Mesh 等子资源使用 `主UUID@子ID`，`.scene` 的 skybox 引用 `@b47c0` 子资源。 | 必须按**实际被引用的子资源**追依赖，不能仅看源文件主 UUID；两代 `.meta` 格式不可相互改写。导入器本体不由运行时 Asset Manager 证明。 |
| 按路径动态加载 | `cc.resources.load` 或 Bundle 的 `load`；`bundle.js::load` 把相对路径与 Bundle 名交给 `CCAssetManager.loadAny`。 | `resources.load` 或 Bundle 的 `load`；`bundle.ts::load` 以相同请求类别交给 `assetManager.loadAny`。3.8 手册对 SpriteFrame 子资源路径有明确形式。 | 查错时先确认 Bundle、相对路径、类型、子资源后缀及该资源是否在构建配置中；`assets/` 任意文件不自动成为 `resources` 路径。 |
| 预加载后再使用 | `CCAssetManager.js::preloadAny` 走 `preprocess→fetch`；`loadAny` 走 `preprocess→load`。 | `asset-manager.ts::preloadAny/loadAny` 也是两条管线。 | 两版的 preload 完成都不表示 Prefab/Texture 对象已经反序列化，可以直接实例化/渲染。 |
| 相同路径、重定向与生成 URL | `config.js` 同路径未指定类型取首项，场景后缀为 `.fire`；`urlTransformer.js` 解析重定向，再按 UUID、版本和基地址组合 URL。 | `config.ts` 同路径也需用类型消除歧义，场景后缀为 `.scene`；`url-transformer.ts` 在组合前还可能处理资源覆盖。 | 看到“路径正确但类型错”或“需要先加载某 Bundle”时，先看 Config 与重定向；不要直接把 `.meta` 路径拼成运行时 URL。 |
| 文件到对象和依赖 | `load.js` 经 `packManager→parser/deserialize→getDepends→setProperties`，资源初始化钩子为 `asset.onLoad`；存在 `__asyncLoadAssets__` 相关分支。 | `load.ts` 走对应链路，资源初始化钩子为 `asset.onLoaded`；该加载器使用 `reloadAsset` 选项，且路径转换多 `replaceOverrideAsset`。 | 资源钩子不要误认为组件 `onLoad`。3.8 的覆盖替换查 `assetsOverrideMap` 与 `url-transformer.ts`；旧版异步依赖路径不能机械套进新版。 |
| 缓存命中 | `shared.js::assets` 普通缓存，`load.js` 命中时 `addRef`。 | `shared.ts::assets` 在 `EDITOR` 为 `WeakCache`，其他情况为普通 `Cache`；`load.ts` 命中时 `addRef`。 | 需要记录是在编辑器进程、浏览器预览还是发布包运行，尤其不能用编辑器缓存行为推断游戏运行时。 |
| 加载回调与净引用 | `load.js` 虽会在命中/交付时 `addRef`，顶层任务结束前的 `clear(task,true)` 又 `decRef(false)`。预览中同一 SpriteFrame 再次加载前后都为 `refCount=2`；第二份 SceneAsset 已在内存中，故该数字不是启动基线。 | 同样存在请求项清理。预览中冷缓存加载 `hdcSky.prefab` 成功后，回调内 `refCount=0`，对象仍在 `assets` 缓存。 | 不要把“回调成功”当作业务长期持有的引用；长期持有须按手册 `addRef/decRef`。计数应看净值和依赖持有。 |
| SceneAsset 缓存 | `utilities.js::cache` 排除 SceneAsset。 | `utilities.ts::cache` 排除 SceneAsset 和默认资源。 | 不能用 `assetManager.assets.has(sceneUuid) === false` 单独判断场景加载失败；应看 `loadScene` 回调和 Director 的 Scene。 |
| `loadScene` 与场景运行 | `Bundle.loadScene` 返回 `SceneAsset` 并设置场景 `_id`，Director 才运行场景。 | 同样返回 `SceneAsset` 并设置 `scene.id/name`，Director 才运行。 | 下载、构造 Scene、激活场景是不同阶段；排查卡顿或释放时要标明阶段。 |
| 切换旧场景 | `CCDirector.runSceneImmediate` 中 `_autoRelease` 在旧 Scene `destroy` 前；`releaseManager.js` 根据旧 Scene 依赖、`autoReleaseAssets` 和常驻节点做引用转移。 | `Director.runSceneImmediate` 中旧 Scene `destroy` 在 `_autoRelease` 前，两者仍在延迟销毁清理之前；`release-manager.ts` 处理旧 Scene 与常驻节点依赖。 | 两版不能假设相同精确调用顺序。两个示例源场景的 `autoReleaseAssets` 都是 `false`；真实磁盘场景切换的 `true` 分支通过运行时设置活动 Scene 验证，源文件没有改为 `true`。 |
| 真实磁盘场景切换与旧资源 | Chrome 与 Mac 原生进程均从 `helloworld.fire` 切到编辑器创建的 `stage4-empty.fire`；旧场景独有 SpriteFrame 初始引用 1。默认 `false` 后引用 0 且继续缓存；独立启动中运行时设 `true`，回调时仍缓存，350ms 采样已移出缓存并失效。 | Chrome 与 Mac 原生进程均从 `main.scene` 切到编辑器创建的 `stage4-empty.scene`；旧场景独有 `soldier.prefab` 初始引用 1。`false` 后引用 0 且继续缓存；运行时设 `true` 后回调时仍缓存，350ms 采样已移出缓存并失效。 | 两版 `director.loadScene` 均加载真实第二磁盘场景；[2.x Chrome](../agent-foundation/traces/2.4.15-disk-scene-switch.jsonl)、[3.x Chrome](../agent-foundation/traces/3.8.7-disk-scene-switch.jsonl)及[2.x Mac](../agent-foundation/traces/2.4.15-mac-native-disk-scene-switch.jsonl)、[3.x Mac](../agent-foundation/traces/3.8.7-mac-native-disk-scene-switch.jsonl)原始记录均可查。源场景仍为 `false`，开启分支只修改活动旧 Scene；350ms 是采样等待，不代表固定延迟。 |
| 显式释放资源 | `releaseAsset`、`Bundle.release`、`releaseAll` 给目标传 `force=true`；`releaseUnusedAssets` 非强制。 | 同样区分强制与非强制；额外有 `_dontDestroyAssets`，且 `EDITOR` 分支的销毁规则不同。 | `releaseAsset` 会跳过**目标根资源**引用数保护；依赖递归仍按非强制判断。仍在使用的资源不可用强制释放作为“无引用”测试。 |
| 隔离运行验证 | 内存 Scene + 仅属于旧场景的内存 Asset 直接调用 `_autoRelease`：开关为 false 时 `refCount=0` 但仍缓存有效，true 时缓存移除且失效。独立 Asset 在 `refCount=1` 时非强制尝试保留，`releaseAsset` 强制移除。另通过 Director 真正切换内存 Scene 复现开关分支，并验证常驻节点资源的转移与移除后释放。 | 同样的直接调用 `_autoRelease` 内存测试得到相同分支结果；Director 真正切换内存 Scene 也复现开关分支及常驻节点资源转移。真实 `hdcSky.prefab` 的冷缓存 preload/load/decRef 另有记录。 | 两版都已验证释放管理器分支和 Director 内存 Scene 切换；它们不覆盖磁盘场景的复杂依赖与其他平台。 |
| 常驻节点资源跨场景 | `game.addPersistRootNode` 会收集组件属性里的 Asset、增加引用；切换时 `_autoRelease` 将依赖登记到新 Scene 的 `persistDeps`，移除常驻身份并再次切场景后可释放。 | `director.addPersistRootNode` 通过相应的 `visitNode/visitComponent` 收集 Asset，转移和后续释放结果与 2.x 内存探针一致。 | 两版公开的常驻节点入口不同；追踪资源时还须看新场景的依赖记录。内存 Scene 若没有该记录，会漏掉 `persistDeps` 转移，不能当作正常加载场景的结果。 |
| 移除 Bundle | `CCAssetManager.removeBundle` 调 `_destroy` 并移除 Bundle 缓存，不替你释放已加载 Asset。 | `AssetManager.removeBundle` 同样明确不自动释放 Bundle 内的 Asset。 | 加载配置、Asset 实例和下载文件缓存是不同层，分别检查。 |
| 从新源文件导入到冷缓存加载 | Creator 2.4.15 给 `resources/stage4-probe.json` 生成 `json` `.meta` 和 `library/imports/` 产物；Chrome 中 `cc.resources.load` 从未缓存状态取得 `cc_JsonAsset`，回调净引用为 0，探针自身 `addRef/decRef` 后失效。 | Creator 3.8.7 给独立的同名 JSON 生成 `json` `.meta` 和 `library/` 产物；Chrome 中 `resources.load` 取得 `JsonAsset`，缓存、净引用和探针释放结果与 2.x 相同。 | 两版均打通源文件、编辑器导入、Bundle 路径及浏览器资源对象，但 UUID、生成目录和对象类型各属其版本；保留各自 `.meta`。 |
| Mac 原生包加载场景与 JSON | Mac 构建、编译、运行成功，窗口显示 `Hello, World!`；JSON 冷缓存加载及真实磁盘场景切换均有原生记录。 | Mac 构建、Make、运行成功，窗口显示 3D 场景；JSON 冷缓存加载及真实磁盘场景切换均有原生记录。 | JSON 生命周期见各自 `*-mac-native-asset-lifecycle.jsonl`，真实场景切换见 `*-mac-native-disk-scene-switch.jsonl`。这些记录仅覆盖当前 Mac 包、示例资源和开关条件，不代表其他原生平台。 |

## 给后续 Cocos agent 的诊断约束

Agent 应先识别 Creator 版本与运行环境，再按该版本手册确定合法入口；从源 `.meta`、场景引用、Bundle 配置、运行时缓存逐层建立证据，最后判断引用是否安全。面对“场景切换后内存没降”时，优先检查 `autoReleaseAssets`、动态持有和其他引用；面对“资源变黑/失效”时，查是否对在用资源调用了强制释放。没有运行时记录时将调用链标成源码结论，不能编造 `refCount` 数字、回调顺序或下载次数。

已验证的切口：3.x 对未被当前场景直接引用的 `hdcSky.prefab`，`preloadAny` 后缓存仍无对象，`loadAny` 后出现 Prefab 且净 `refCount=0`；显式 `addRef` 后非强制释放保留它，`decRef` 后异步移除。两版都已对隔离的内存 Scene 直接执行 `_autoRelease` 的开/关分支，对隔离 Asset 验证强制释放，也都通过 Director 真正切换内存 Scene 验证自动释放和常驻节点资源转移。随后各自从真实磁盘场景读取运行时依赖图，在编辑器导入最小 JSON，并在 Chrome 预览及 Mac 原生进程中分别完成冷缓存加载、引用保护与释放观测。现在两版 Chrome 预览还分别验证了旧磁盘场景独有资源在真实 `loadScene` 切换后随 `autoReleaseAssets` 开关的缓存状态；Mac 原生包的磁盘场景切换与 Android/iOS 仍没有对应打点。
