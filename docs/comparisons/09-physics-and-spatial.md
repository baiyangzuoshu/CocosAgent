# 阶段 9：同一物理行为的两版实现对照（源码研究中）

本页只比较开发者同一目的的实现路径。两版公开行为以各自[2.4 物理手册](https://docs.cocos.com/creator/2.4/manual/zh/physics/index.html)、[3.8 物理手册](https://docs.cocos.com/creator/3.8/manual/zh/physics/index.html)为基线，内部细节分别见[2.x 独立笔记](../2.x/09-physics-and-spatial.md)与[3.x 独立笔记](../3.x/09-physics-and-spatial.md)。当前局部 Web 轨迹覆盖两版 3D 射线及当前 Cannon/Bullet 的自然帧 3D 事件、两版当前 Box2D 的自然帧移动刚体同步、2.4 的 2D 查询与普通碰撞，以及 3.8 TypeScript Box2D 的查询和接触监听门槛；其他后端仍待验证。

| 游戏开发行为 | 2.4.15 路径 | 3.8.7 路径 |
| --- | --- | --- |
| 只检测 2D 形状相交 | 单独的 `cc.CollisionManager` + 普通 `cc.BoxCollider` 等；默认需手动启用，向节点脚本调用 `onCollisionEnter/Stay/Exit(other,self)`。按单向组矩阵建立候选配对，接触中禁用或改组可直接触发 `Exit`。 | `PhysicsSystem2D` 选 Builtin；在 `Collider2D` 或系统上订阅 `Contact2DType`，Builtin 只产生 BEGIN/END，源码不传接触对象。组矩阵需双向允许，接触中移除或改组可直接发 END。两者都不提供完整动力学，但回调与过滤条件不同。 |
| 用 2D 刚体解决碰撞 | 单独的 `cc.PhysicsManager` + Box2D；默认关闭，监听需刚体开启 `enabledContactListener`，节点脚本收 `onBeginContact(contact,self,other)` 等。默认每帧按 `1/config.frameRate` 步进，累积器可选。 | `PhysicsSystem2D` 选 Box2D 后端；Collider2D/系统事件订阅，三个 Box2D 包装器源码均要求至少一侧 RigidBody2D 开启监听才产生系统级接触回调。固定步长累积模拟位于 Director `postUpdate`。 |
| 3D 触发/刚体碰撞 | `cc.Physics3DManager`；预览 Cannon，构建可选 Cannon/Builtin；Builtin 只有触发器语义，管理器默认关闭。按 2.4 手册在 `Collider3D.on` 订阅 `trigger-enter`/`collision-enter` 等连字符名称；本快照 Cannon 另发 `onTrigger…`/`onCollision…` 兼容名，Builtin 没有这条兼容路径。 | `PhysicsSystem` 配选择器；Builtin/Cannon/Bullet/PhysX。默认后端以 3.8 手册为准，实际工程看功能裁剪。`Collider.on` 使用 `onTrigger…`/`onCollision…` 名称并更新事件需求标记。Builtin 只支持触发器语义；系统在 Director `postUpdate` 逐子步同步、模拟和派发。 |
| 2D 点、矩形与射线查询 | Box2D `testPoint(worldPoint)` 返回单个 Collider 或 `null`，`testAABB` 与 `rayCast(p1,p2,type)` 返回数组。本快照两个 AABB 查询只收集 Dynamic 刚体；Web 实测 Static fixture 不命中，Dynamic 传感器覆盖点时命中。 | `PhysicsSystem2D.testPoint/testAABB` 在 Builtin、TypeScript Box2D、Box2D WASM 和 JSB 包装器源码中都返回复用数组；Builtin `raycast` 恒返回空数组，官网把射线测试限定为 Box2D。3.8 手册把点测试写成单对象，与其 API 参考及 3.8.7 源码不一致。 |
| 3D 射线查询 | `Physics3DManager.raycast(worldRay, group, maxDistance, queryTrigger)` 返回结果数组或 null，Closest 返回单结果。3D Builtin 也实现射线，按查询组矩阵过滤，但源码未使用 `queryTrigger`；另有不依赖物理 Collider 的 3D 几何模型相交 API。 | `PhysicsSystem.raycast/raycastClosest(worldRay, mask, maxDistance, queryTrigger)` 返回布尔值，从系统结果字段读取复用数据。3D Builtin 也实现射线，按 `mask` 过滤，但源码未使用 `queryTrigger`，命中法线为零向量。相机屏幕点转射线与物理命中是两个步骤。 |
| 3D 几何扫掠 | 2.4 本轮研究的 3D 物理管理器没有 3.8 的 `sweepBox/Sphere/Capsule` 接口；不要把射线或几何相交 API 当作扫掠。 | 3.8 手册提供三种形状及 Closest 变体；本快照 Builtin、Cannon 的 World 方法警告并返回 `false`，Bullet、PhysX 则有实现。诊断空结果必须先确认后端。 |
| 确认实际 3D 后端 | 构建宏 `CC_PHYSICS_CANNON/BUILTIN` 控制 `instantiate` 绑定的构造器；Director 还要确认模块存在才创建 `Physics3DManager`。预览 Cannon、构建选择以 2.4 手册为准。 | 导入的后端模块在 `Game.EVENT_PRE_SUBSYSTEM_INIT` 注册选择器，`DirectorEvent.INIT` 再按项目设置和手动加载条件创建系统与 World。后端 ID、系统实例、World 应分别核对。 |

3D 事件的公开前提不能跨版本套用：2.4 事件手册列出事件名称与订阅方式，没有刚体类型矩阵；3.8 手册明确非 Builtin trigger 至少一侧非静态。3.8 同一事件页的碰撞段落与类型表写“至少一侧非静态”，后面的区别段落写“至少一侧动力学”；本次 Bullet Web 的 Kinematic 对 Static 碰撞实际发了 `onCollisionEnter`，支持前一种写法，但不能据此改写其他后端。两版 Collider 源码注释均写明 Builtin 中始终按 trigger 处理，Builtin Shape 的 `isTrigger` setter 为空；因而形状配对不按该布尔值过滤。这里是静态源码结论，尚无 Builtin 运行轨迹；已备好[2.4](../agent-foundation/probes/stage9-3d-builtin-events-2.4.js)与[3.8](../agent-foundation/probes/stage9-3d-builtin-events-3.8.js)探针，逐版比较 collider-collider、trigger-collider 与 trigger-trigger，并同时监听 collision 回调。探针只在对应 Builtin World 下运行，不外推至其他后端。

对 agent 最重要的判别顺序是：版本 → 2D/3D → 简单相交还是动力学 → 当前后端 → 组件/系统启用与监听条件 → 帧步进 → 事件或查询结果。表中“默认”指手册或本地源码默认值，不能推断两个示例的运行设置。下一步补 3D Builtin 及其他后端事件；保留事件原始轨迹。

3.8 2D `.instance` 会懒创建 World，检查后端时先读 `PHYSICS_NONE`；不要在验证中调用 `selector.switchTo`，本快照 2D 切换未销毁旧 World。两版的后端切换和组件事件均需在各自工程、各自平台验证。

2026-10-05 的[两版后端快照](../agent-foundation/traces/stage9-backend-web.jsonl)使“实际预览后端”具体化：2.4 有 `CannonWorld` 但 3D 管理器未启用；3.8 2D 是 TypeScript Box2D、3D 是启用的 Bullet。3.8 [点查询轨迹](../agent-foundation/traces/3.8.7-stage9-2d-query-web.jsonl)返回复用数组，与此前 2.4 [Box2D 轨迹](../agent-foundation/traces/2.4.15-stage9-2d-query-web.jsonl)的单对象 `testPoint` 构成同一开发行为的运行对照。两次实验的对象/后端条件不同，只能确认返回形状差异，不能比较接触时序或射线性能。

两版随后使用**同尺寸、同起点和方向**的临时 Box Collider 补了[3D 射线轨迹](../agent-foundation/traces/stage9-3d-ray-web.jsonl)：2.4 临时启用 Cannon 管理器后，`raycastClosest` 返回对象，距离 9、点 `(20000,20000,-1)`；3.8 当前 Bullet 系统的 `raycastClosest` 返回布尔值，详细结果放在 `raycastClosestResult`，距离约 9、法线 `(0,0,-1)`；两版偏移射线均未命中。比较的是各自**当前不同后端**的公共用法与结果形状，不是 Cannon 与 Bullet 的性能或所有后端的等价性。3D 事件的当前后端运行对照见下段。

3.8 的[TypeScript Box2D 接触轨迹](../agent-foundation/traces/3.8.7-stage9-2d-contact-web.jsonl)验证了本次手动步进中至少一侧刚体开启 `enabledContactListener` 才收到 Collider/系统 Begin。两版源码都在 fixture 建立时按监听开关登记，派发时再次检查开关。2.4 的[三组对照轨迹](../agent-foundation/traces/2.4.15-stage9-2d-contact-web.jsonl)进一步验证：关闭监听时无回调，创建前开启时收到 Begin，创建后才开启不会补登记；禁用正在接触的另一 Collider 后，仍启用的一侧收到 End。两版实验均是手动步进，未证明自然帧回调顺序；3.8 创建后切换监听的隔离运行对照见下段。

监听状态运行中切换的源码恢复路径也有版本差别：2.4 需让 Collider 生命周期重新初始化以重建 fixture；3.8 的 `Collider2D.apply()` 明确销毁并重建 shape/fixture，会按当前刚体字段重新登记。两边都不是单改 `enabledContactListener` 就动态订阅现存 fixture。[2.4 对照探针](../agent-foundation/probes/stage9-2d-contact-registration-2.4.js)已有[当前 Box2D Web 轨迹](../agent-foundation/traces/2.4.15-stage9-2d-listener-reenable-headless-web.jsonl)：只切字段的 A 登记数为 0、无 Begin；关闭再启用 Collider 的 A 登记数为 1、收到 Begin。[3.8 对照探针](../agent-foundation/probes/stage9-2d-contact-registration-3.8.js)已有[当前 TypeScript Box2D Web 轨迹](../agent-foundation/traces/3.8.7-stage9-2d-listener-apply-headless-web.jsonl)：初始变换标志清零、两对传感器分离之后再开监听并移入重叠；只切字段的 A 登记数仍为 0、无 Begin，`apply()` 的 A 登记数为 1，收到 Collider 与系统 Begin。新节点变换脏时 `syncSceneToPhysics` 可因缩放标志重建 fixture，所以运行条件必须记录。

自然帧的**已测标记顺序**不同：[2.4 Box2D 轨迹](../agent-foundation/traces/2.4.15-stage9-2d-natural-frame-headless-web.jsonl)在同帧为 `BEFORE_UPDATE → Begin(A/B) → AFTER_UPDATE`；[3.8 TypeScript Box2D 轨迹](../agent-foundation/traces/3.8.7-stage9-2d-natural-frame-headless-web.jsonl)为 `BEFORE_UPDATE → AFTER_UPDATE → BEFORE_PHYSICS(2D) → Begin(A/B) → AFTER_PHYSICS(2D)`。3.8 的同帧还有一组 `BEFORE/AFTER_PHYSICS(3D)`，来自当前启用的 Bullet 系统；两个系统共用 Director 事件名，不能把两组标记误认为 Box2D 的两个子步，探针记录的 `maxSubSteps=1`。源码进一步定位：2.4 `CCPhysicsManager.update` 由 Scheduler 在组件 `update/lateUpdate` 之间执行；3.8 2D `postUpdate` 在组件 `lateUpdate` 之后。

[移动刚体对照](../agent-foundation/traces/2.4.15-stage9-2d-moving-sync-headless-web.jsonl)与[3.8 对照](../agent-foundation/traces/3.8.7-stage9-2d-moving-sync-headless-web.jsonl)补齐了当前 Web 后端的节点回写观测：两个初始重叠的 Dynamic 传感器中，A 以约 320 场景单位/秒移动。2.4 首帧组件 `update` 和 Begin 读 `120000`，同帧 `lateUpdate` 读 `120005.333…`；3.8 首帧 `update/lateUpdate` 和 Begin 读 `120000`，2D `AFTER_PHYSICS` 才读 `120005.3359375`，下一帧组件 `update` 可读到回写值。接触首帧初始重叠，无法由它推断所有碰撞回调中节点与 Box2D 位置的关系。2.4 探针临时开启原先关闭的管理器；3.8 探针临时标记 2D/3D 系统来源。两版示例所用预览是否链接相邻源码构建尚未确认。

两版可复跑探针为[2.4 静态脚本](../agent-foundation/probes/stage9-natural-frame-2d-2.4.js)、[3.8 静态脚本](../agent-foundation/probes/stage9-natural-frame-2d-3.8.js)和各自[2.4 移动脚本](../agent-foundation/probes/stage9-moving-sync-2d-2.4.js)、[3.8 移动脚本](../agent-foundation/probes/stage9-moving-sync-2d-3.8.js)，均只构造临时 Web 预览对象，不写回场景。其他 Box2D 包装器与原生仍须另取轨迹。

3D 事件的当前后端对照已完成：[2.4 Cannon 轨迹](../agent-foundation/traces/2.4.15-stage9-3d-events-headless-web.jsonl)记录 27 个 `AFTER_PHYSICS`，静态 trigger、Dynamic trigger 和 Kinematic 对 Static 的非 trigger 盒均向两侧发 trigger Enter；Dynamic 对 Static 的非 trigger 盒发 collision Enter（4 contacts）。Cannon 同时发 2.4 手册连字符名和 `onTrigger…/onCollision…` 兼容名。[3.8 Bullet 轨迹](../agent-foundation/traces/3.8.7-stage9-3d-events-headless-web.jsonl)记录 24 个 `AFTER_PHYSICS`，静态 trigger 无 Enter、Dynamic trigger 发 trigger Enter，Dynamic 与 **Kinematic 对 Static 的非 trigger 盒**都发 collision Enter（各 4 contacts）。2.4 的 Kinematic/Static 在随源码附带的 Cannon `Narrowphase.getContacts` 中被设为 `justTest`，进入 trigger 字典；3.8 Bullet 则按非 trigger 接触派碰撞。两次均是各自当前后端，不构成同后端跨版本等价测试，且相邻源码构建来源未确认。
